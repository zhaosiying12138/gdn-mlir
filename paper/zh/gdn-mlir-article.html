GDN-MLIR：Gated DeltaNet 算子的 MLIR 渐进式下降编译器

从语义 op 到 sm_120a cubin：编译期调度、PTX 级覆盖证明与交错配对性能裁决

本文描述 GDN-MLIR：Gated DeltaNet（chunk_gated_delta_rule，线性注意力家族中带门控 delta rule 的算子）前向与反向算子的编译器。编译器接受一个只声明语义的方言 op，经 L0（语义）、L1（算法结构）、L2（调度）、L3（张量核与流水）、L4（sm_120a 目标代码）五层渐进式下降，产出可直接装载的 cubin。实现全部建立在 stock MLIR（2026-10 LLVM 主干）之上，引入的自定义 NVVM op 为 1 个（预算上限 5 个）。

核心主张有四条。其一，表达力：fla（Triton）与 FlashQLA（TileLang）两家手写实现的 PTX 指令族与调度结构均落在编译器旋钮空间的覆盖范围内，复现一个参考实现等价于选择一组旋钮取值。其二，调度：调度决策在编译期由 Z3 约束求解与一次性硬件标定的解析成本模型完成，新形状调度耗时 0.8 秒纯 CPU，两次完整编译逐字节一致，排序与实测的 Spearman 秩相关为 0.8962。其三，性能：前向三个基准形状在两类负载窗口下全面超过 fla Triton（最好 2.125 倍，详见表 1），反向小形状 1.72 倍。其四，边界：反向大形状为 0.41–0.49 倍，四类独立分析表明该值由梯度容差合同决定——在 fla 的容差下，理想执行的上限为 0.85–0.92 倍。

全部实验在同一环境完成：RTX 5090 Laptop（Blackwell sm_120a，82 SM，24GB），WSL2，CUDA 13.x，bf16 输入与 fp32 累加，K=V=128。形状记号 B·T·H 表示批大小、序列长度与头数；基线为 fla 的纯 Triton 路径（FLA_FLASH_QLA=0）。

一、测量口径与核心结果

1. 交错终判与窗口口径

所有性能对比采用交错终判（interleaved adjudication）：在同一 GPU 窗口内，将本方与基线置于同一进程、同一位相同的输入上交替成对计时，每形状 30 对；点估计取逐对比值的中位数，显著性由精确符号检验给出。共载（co-load）指测量窗口内 GPU 上常驻其它计算任务，空闲窗口指无其它计算任务。采用该口径的依据是两条实测事实：分离进程的绝对时延在零负载下仍随时钟状态漂移（同一 cubin 相隔数分钟的两个进程可相差 47%）；同进程内模块加载顺序改变全局内存布局，使访存最重的 kernel 出现约 6% 的系统性偏差，加载顺序互换偏差精确反号。绝对时延不可跨窗口比较，两类窗口分别报告。

二、背景：算子与手写路线的代价

1. 算子的数学结构

Gated DeltaNet 对每个 token 维护一个状态矩阵并按固定顺序递推：

h ← 2^g · h                （衰减在先，g ≤ 0）
b ← β ⊙ (v − k·h)          （delta 修正项）
h ← h + kᵀ ⊗ b             （外积写回）
o ← q · h

四步顺序不可交换，属于语义契约。按扫描直接实现时每个 token 读写一遍 K×V 状态，带宽不可承受。fla 一系的 chunk 化将递推改写为矩阵乘：一个 chunk 内 C 步递推对状态构成一个仿射映射，这是从扫描到矩阵乘的转换枢纽。

chunk 化的第一步是解出 chunk 内全部 token 的修正项。注意每个 token 的修正项 b_i 依赖当时的状态，而状态又依赖同一 chunk 内更早 token 的修正——把这 C 个相互依赖的方程联立求解，恰好得到一个下三角线性系统（每个 token 只依赖更早的 token）。该系统就是 KKT 矩阵 A = strict_tril( β ⊙ (k·kᵀ) ⊙ 2^(gc_i−gc_j) )：严格下三角，I+A 为单位下三角，其逆 T = (I+A)^(−1) 由前代换求得——按时间顺序逐行求解，无主元选取、无除法。数值稳定性有三个结构性来源：键向量经 L2 归一化使内积不超过 1、β ∈ (0,1)、衰减因子单调不超过 1。

第二步是跨 chunk 的状态传递。衰减只通过两个显式因子进入：状态上的 2^gcl 与键行上的 2^(gcl−gc)，每个 chunk 将整段历史衰减折叠为对入口状态的一次乘法，即 S′ = (2^gcl·I − k̃ᵀw)·S + k̃ᵀu。第三步是输出分解 o = o_intra + o_inter，chunk 内贡献与携带状态贡献相加。

反向传播中最微妙的一步是 dA 的收缩。单侧近似重复计数直达项并丢失交叉项（C=3 反例在符号层面将其否定），正确形式为双侧掩蔽收缩 dA = −strict_tril( Tᵀ · strict_tril(G) · Tᵀ )，与 fla 的 prepare_wy_repr_bwd 等价。

2. 手写路线的代价

该算子目前由手写内核服务：fla 基于 Triton，运行时 autotune，每形状首次搜索需要 39.8 秒设备时间；FlashQLA 基于 TileLang，手写 warp 专化调度。TileLang 自身的 z3 调度器只存在于 Ascend 后端，CUDA 侧退化为运行时搜索。手写路线有两个结构性代价：调度知识不可组合，每个新形状与新算子需要重新手写；调度决策推迟到运行时，产生冷启动与部署开销。

本项目将调度从内核源码中抽出，变为编译期可求解的问题：调度以 IR 表达（transform dialect 参数化工件与方言属性承载全部旋钮），合法性由 Z3 判定，优劣由校准解析成本模型排序，正确性由分层验证把关。参考实现由此成为旋钮空间中的坐标。

四、L0 语义层

L0 只声明意图，展开选择全部留给下层。数值约定（衰减在先、β 作用于修正项、L2 归一化位置）固定于方言 verifier 与生成器。GDN 的数值约定密集，任何一条弄错都会产生形状正确而数值整体错误的静默偏移，因此语义只有一份。

gdn.fwd 接收 q、k、v、β、g 与可选初始状态 h0，输出 o 与终态 ht；gdn.bwd 输出六个梯度 dq、dk、dv、dβ、dg、dh0。GdnConfigAttr 捆绑七个语义旋钮（chunk_size、use_g、use_gk、normalize_q、use_initial_state、store_final_state、is_varlen），它们改变算子的数学形态，与 L2 的调度旋钮分属两个层面：

%o, %ht = "gdn.fwd"(%q, %k, %v, %beta, %g, %h0)
    <{config = #gdn.config<64, true, false, true, true, true, false>}>
    : (...) -> (tensor<2x128x2x16xf32>, tensor<2x2x16x16xf32>)

为审计偏离 stock MLIR 的程度，全部硬件专用指令入口集中登记为 12 个方言 op，下降时一一映射到树内 nvgpu/nvvm op：setmaxnreg（warp 专化寄存器再分配）、elect（leader 选举）、mbarrier 四件（异步屏障）、TMA 三件（张量搬运）、bulk 两件（异步组控制）。其中 11 个为树内 op 的逐字段薄封装；唯一需要自定义实现的是 gdn.mma.tf32k8（第十一节）。2026-10 LLVM 主干已原生支持其中大部分指令词汇，薄封装的价值在于过渡期可用与预算可审计。

五、L1 算法结构层

chunk-WY 分解在 L1 表达为真实的 linalg 加 scf MLIR，在 CPU 上经 11 个树内 pass 下降后由 mlir-runner 执行。前代换求逆 T = (I+A)^(−1) 的真实 IR 节选如下（自验证证据树）——算法直接写在 IR 中，无库调用、无黑盒 op：

linalg.fill ins(%f0 : f32) outs(%Tbuf : memref<64x64xf32>)
scf.for %i2 = %c0 to %cC step %c1 {
  memref.store %f1, %Tbuf[%i2, %i2] : memref<64x64xf32>          // 单位对角
  scf.for %j2 = %c0 to %i2 step %c1 {
    %sum = scf.for %k2 = %j2 to %i2 step %c1 iter_args(%acc2 = %f0) -> (f32) {
      %aik = memref.load %Abuf[%i2, %k2] : memref<64x64xf32>
      %tkj = memref.load %Tbuf[%k2, %j2] : memref<64x64xf32>
      %ak  = arith.addf %acc2, arith.mulf %aik, %tkj : f32
      scf.yield %ak : f32
    }
    %neg = arith.negf %sum : f32
    memref.store %neg, %Tbuf[%i2, %j2] : memref<64x64xf32>       // T[i,j] = −Σ A[i,k]·T[k,j]
  }
}

三角掩蔽同样以控制流表达：A 的构造用严格小于的比较（strict_tril），P 的构造仅将谓词换为小于等于（含对角），同一手法只差一个比较谓词。L1 的每条已知边界同时是 L2 的旋钮接口：前代换刻意保持显式，算法变体由下层 solve 旋钮决定；中间量物化还是重算，由 recompute 旋钮决定。

验证采用三方交叉：JAX fp64 可执行规约（顺序递推、分块、jax.vjp 三实现互证）为语义单一事实源。JAX 自检 44/44 项，分块与顺序两条独立路径在 fp64 下相差 5.6e-16（舍入量级）；MLIR L1 对 JAX 前向约 6e-7、反向六梯度最差 6.4e-6；JAX 对 fla naive 前向 1.2e-7、反向 2.3e-6（fla naive 内部固定 fp32，对照取 fp32 口径，经 fp64 JAX 中转）。三方闭合，评分参考自身先被验证。

六、L2 调度层：编译期调度

1. 旋钮空间与调度 IR

每份内核是一个参数化 transform 工件加一组旋钮取值的实例化，即调度以 IR 表达。旋钮空间十维：dtype（bf16/f32）、mma 精度（bf16/tf32）、tile 的 M/N/K（32/64/128）、warps（2/4/8）、流水深度（0/2/3）、mma 开关、warp 专化、TMA。transform dialect 的有效写法逐个验证；两个边界写法由实测排除：树内 create_async_groups 在每组异步复制后立即插入 wait_group 0，复制结构性无法与计算重叠，异步 staging 须手动发射；staging 地址须线程跨步，block-uniform 形态会被每线程重复执行 256 次。

2. Z3 合法性求解

决策变量为十维旋钮向量（固定声明序）。约束三类：旋钮耦合（bf16 输入只匹配 bf16 mma）；结构合法性（tile 尺寸对齐、流水深度不超过 K 的趟数、TMA 依赖 warp 专化）；资源容量（显式共享内存字节模型加寄存器约束 32·(w+w_spec)·255 ≤ 65,536）。目标函数含非线性项，无法交给 Z3 的 Optimize 模式，故用 SAT 加阻塞子句做全空间枚举、在求解器外按预测时间排序。kkt 阶段 368 个合法配置 0.29 秒枚举完毕，o 阶段 465 个配置 0.33 秒；空间穷尽性由 unsat 判定背书，固定种子与固定声明序保证两次运行逐字节一致。

两处防御性设计保证解的合法性：求解器对被其余指派唯一决定的变量可能不返回取值，此时固定其余指派、逐候选 SAT 探测补全，杜绝向下游注入非法值；枚举若因资源上限截断而非完备终止，重试一次，仍失败即抛异常拒绝输出——残缺空间中的排序没有意义。

3. 校准成本模型

成本模型不含任何对实测配置时间调参的自由常数：每个速率来自一次性标定或为文档化的 sm_120 结构常数。模型每项为"计数除以速率"，分子的指令计数在编译期精确——18 个配置的静态 PTX 自检中，mma.sync、ld.shared、bar.sync 计数 18/18 精确，cp.async 偏差不超过 1.6%。误差只剩分母。一次性标定表由六个微基准 kernel 构成，分钟级、显存低于 2GB，属单次沉没成本：

4. 搜索成本

本方每新形状 0.8 秒纯 CPU，对 fla 首搜 39.8 秒设备时间约 50 倍；fla 磁盘缓存摊销后 7.7–67 倍。部署形态的差别更大：本方产出 AOT cubin，新进程冷启动约 27 微秒；fla 每个形状在新进程内重新 autotune，缓存命中亦需 0.65–5.67 秒。

七、L3 机器层

机器层的机制按功能分五组陈述。各组机制在最终配置中同时生效。

1. 数值到指令的映射：split-bf16 hi/lo mma

反向链的多数 GEMM 有一侧操作数必须是 fp32 中间量——这些中间量存在大数相消，直接以 bf16 存储会在读取时破坏精度（第十二节的误差预算给出完整分析）。张量核对这类乘积提供三种精度：bf16（7 位尾数，截断指数域）、tf32（10 位尾数）、fp32。前两种都不够：tf32 在 dkb 位点使 dk 输出误差达到 1.04e-2，超出 8e-3 容差。最终方案将 fp32 值拆为两个 bf16（一处 GEMM 调用位置下文简称位点）：

hi = bf16(x)          lo = bf16(x − hi)        // hi+lo 在 fp32 中精确可加（8+8 位尾数装进 24 位）
A·B ≈ hi_A·hi_B + hi_A·lo_B + lo_A·hi_B          // 三条 bf16 mma 以 fp32 累加器链接；lo·lo（约 2⁻³²）舍弃

两条代数性质各省一条 mma。其一，行尺度折入 epilogue：缩放因子只依赖输出行时，缩放完全移出缩并、在 epilogue 做一次标量乘，dvp_bh 位点由 3-mma 降为 2-mma。其二，2 的幂尺度可交换性 split(v·2^d) = split(v)·2^d 精确成立：caryA 的预乘 tile 由此退化为原样拷贝，共享内存从 82,176B 降至 28,592B，寄存器从 255 降至 76，该 kernel 提速 5.00 倍。这是改结合方式而不改任何值的机器级表达。

2. 算法级改写：扫描的仿射携带形式

反向 dh 递推每 chunk 原需 8 段 GEMM 的串行链。代数重结合（非近似，fp64 对照 2–3 ulp）将其改写为携带形式 Xₙ₋₁ = Aₙ·Xₙ + Bₙ。携带形式的价值在于复合满足结合律且每个块只与其前驱交互，于是可以拆成三部分：携带算子的并行预复合（相邻块的 Aₙ 先乘）、每步仅 1 个 GEMM 的携带链、部分和的独立重算。两个数学性质保证正确与可并行：算子超收缩（谱范数不超过 2.3e-18）使复合误差不随链长放大；Aₙ 与 v 切片无关，一次复合服务全部列切片。扫描族整体从 3.13 毫秒降至约 1.02 毫秒。

3. 数据通路：异步 staging、乒乓预取、warp 专化与 TMA

异步复制（cp.async，16B 粒度）由生成器手动发射，地址线程跨步。一条数据完整性规则伴随整条通路：cp.async 写入的 tile 经 ld.shared 读回正确、经 ldmatrix 读回错误，损坏仅出现在与构建调度相关的行块子集上；读回路径须经 st.shared 或逐元素重写。

串行链上的段进入组 A/B 乒乓缓冲后，装载与计算重叠。两个实例：F2 的 u 段（2 字节装载配 4 字节跨距，将 4KB 放大为约 8KB 内存扇区）进入乒乓后单 kernel 减少 104.5 微秒，60 对测量中零对变慢；寄存器累加 GEMM 的 A 窗口乒乓是扫描链提速的组成部分。

warp 专化（同一线程块内生产者与消费者 warp 分工）下，生产者 warp 选举 leader 发射 TMA（张量内存加速器，宿主侧构造描述符），消费者 warp 以纯数据就绪的 mbarrier 协议等待；setmaxnreg 在 warp 间再分配寄存器，实测某 kernel 溢出从 22,844B 降至 48B。TMA 描述符的维序契约为：encode 时维度反序、坐标不反、目的地址要求共享内存 128B 对齐。

4. 存储几何：bank 冲突、垫行与 32 位宽存

共享内存按 32 个 bank 组织，每 bank 宽 4 字节；同一 warp 的 32 个线程并发访问的字地址落入同一 bank 时串行化。读侧解法为垫行：被 ldmatrix 读取的 tile 行距恰为 128B 整数倍时，8 行落入同一 4-bank 组形成 8 路冲突；每 tile 增加 8 列 bf16（16 字节）使行距错开，F2 从 473 降至 249 微秒，为前向单笔最大杠杆。

写侧解法为 WST 加 W32P。WST 将相邻 cell 配对成 32 位读写，指令与循环迭代减半；直接配对使两个半 warp 的字地址落入同一 bank 组（实测反慢 4.3 微秒）。W32P 在生成器层重排 lane 到行的映射：lane 0–15 读行 r、lane 16–31 读行 r+4；F2 的 tile 行距为 80 字节即 20 个字，两个半 warp 的字地址分别落在 20r 至 20r+15 与 20r+80 至 20r+95 区间，而 80 mod 32 = 16，两个区间恰好命中 32 个 bank 的两个互补 16-bank 半区，冲突清零。该变换为纯下标算术，不影响共享内存池与占用；F2 在七个场景减少 17.9–22.6 微秒，与带宽核算一致（0.176 µs/MB × 100.6 MB ≈ 17 µs 上限）。

5. 驻留资源：生存期别名与寄存器上限

每 SM 同时驻留两个线程块要求每 kernel 静态共享内存池不超过 50.2–50.7 KB。算法 tile 的生存期拼接远超上限，任意时刻活跃字节却在门槛之下。MLIR 的 SSA 合法性要求每 tile 一次分配，"生存期不重叠的 tile 共享字节"这一物理事实在 PTX 后处理层实现：生成器产出布局表（竞技场基址加偏移），后处理按分配尺寸识别 tile 并重写地址。设计立场为：别名是纯增益变换，失败模式必须是"不省"，绝不允许"算错"；任何识别失配整体回退。

驻留资源的作用取决于 kernel 的瓶颈，两组对照给出分解。F1 的停顿 24.3% 来自访存等待（DRAM 利用率仅 56.8%），属延迟受限，驻留翻倍带来 53.5 微秒收益；F3 每次加载约 120 MB，属带宽受限，同样的驻留手段实测反慢 96.1 微秒——强制 F3 单 CTA 为 115.6 微秒，其中 K 循环重排本身约 110 微秒，驻留仅贡献约 20 微秒。占用提升在延迟受限 kernel 上是杠杆，在带宽受限 kernel 上是空转。串行扫描同理：将扫描工作按 K 维拆到多 warp 或多 CTA（含 sm_120 线程块簇；实测簇属性本身零开销，跨 CTA 交换成本 57 微秒），三个数据点均在 0.88–0.99 之间——每 warp 工作量不变时指令级并行已饱和，剩余延迟由数据搬运与同步构成。

八、L4 目标层与 PTX 后处理

目标层命令链为 gpu-lower-to-nvvm-pipeline（cubin-chip=sm_120a）产出 PTX，经 856 行文本改写器 gdn_smem_fix.py 处理，再由 ptxas-blackwell 编译为 cubin，SASS 由 nvdisasm 审计。后处理解决 stock 流水线遗留的四个问题，全部经 GPU 探针或源码级对照确认。

1. 静态共享内存。workgroup 的 memref.alloc 被下译为设备端堆分配，携带共享内存 tile 的 cubin 在真机上全部触发非法地址错误，通过率为零。修复复刻 MLIR 自身为静态共享内存已经使用的写法（.shared 声明、取址改写、128B 对齐）；修复后通过率从零到全量。

2. 生存期别名（第七节第 5 小节）。

3. 寄存器上限注入。ptxas-blackwell 忽略 --maxrregcount 旗标、遵循 PTX 源内 .maxnreg 指令；逐 kernel 入口注入，未匹配显式告警。工程细节：ptxas 报告文件只对应第一次编译，最终 cubin 出自改写后的第二次编译，两次的寄存器分配可能不同，资源对账以第二次为准。

4. bank 几何（第七节第 4 小节）。

同一工具还完成三项工作：多 kernel 合并进单一 cubin（跨 kernel 设备内拷贝消失；重名 .shared 符号被 ptxas 跨入口静默合并导致越界写，须改名）；常数参数字节级替换（20 个 kernel 中 18 个变为零参数，消除最多约 140 条 .b64 常数装载）；cache_key 取全部旋钮环境变量加源码指纹的哈希，键不匹配时缓存自动失效。

2. 确定性

编译端：Z3 固定声明序、种子 7、资源上限 2×10⁷，两次完整编译逐字节一致；生成器同种子两次生成的 MLIR 哈希相同；全部旋钮关断时产物与默认配置逐字节等价（27/27 payload、18/18 cubin）。排名因此是可存档、可 diff、CI 可断言的证据文件。

运行端：同一 cubin、同一输入、同一发射几何下输出逐位一致，跨进程（全新 CUDA 上下文与模块加载）验证 5 次全过方为通过。该协议抓到过五个真实竞态，全部在数值容差之内、多数仅 1–3 ulp——数值验证对这类缺陷无感，逐位一致性是唯一能抓到它们的尺子；其中两个曾被更高的驻留占用掩盖。逐位可复现的代价约 0.3%（T2048）。

十、性能评测

1. 前向：三 kernel 分阶段设计

前向最终形态为三个 kernel 装进单一 cubin：F1 做 token 并行的 WY 预计算（gc 扫描、A、T、u、w），F2 是全算子唯一的跨 chunk 串行链（状态常驻共享内存），F3 从中间量重算输出。单 launch 的 persistent 融合版本实现完整、数值全过，但 WY 预计算从 2048 个 CTA 的并行塌缩进 64-CTA 串行链，端到端 4.53 对 0.785 毫秒（T8192）；融合版本保留为融合边界旋钮的极限端设计记录，正式判定由三 kernel 方案承担。

F1 的时间分布由逐段删除探针测得（删除一个段、测整 kernel 时间差）：uw 段 116.5、kkt 59.5、solve 41.3、gc 扫描 17.6、phase-0 8.4 微秒（T8192，总时延约 227 微秒；各段之和超过总时延，因删除收益含重叠成分）。临界路径在 uw 段；最终配置的主要杠杆（双 CTA 驻留、清零折进空闲线程、垫行、乒乓预取、宽存）集中于该路径。

2. 反向：8-kernel 链

终态反向链为 8 个 kernel：wy（重算 WY 因子，六个梯度均穿过其写入的张量）、五个扫描族 kernel（执行两条方向相反的状态扫描，即第七节第 2 小节的仿射改写）、两个计算族 kernel（dqkwg 组装最大的一组梯度；wyb 执行 dA 双侧掩蔽收缩，产出最终 dk、dβ、dg、dv）。整链从基线 58.88 毫秒优化至 2.15 毫秒；数值侧同步改善，wy 链的 dk 误差从 1.691e-3 收紧至 1.284e-3。

十一、覆盖证明与逃生舱预算

1. 参考 PTX 的纯 CPU 收割与两个极点

两家的 PTX 与 SASS 全部离线获取：fla 经 Triton AOT 以 GPUTarget("cuda",120,32) 目标编译（自带 ptxas -v 资源日志）；FlashQLA 经 TileLang 锁定 target 后导出 kernel 源；SASS 经 nvdisasm 反汇编。两家构成调度谱系的两个极点：fla 寄存器 40–255 顶格、大量溢出、多级流水、无 warp 专化、循环全展开；FlashQLA 寄存器 88–128 由 setmaxnreg 固定、TMA 加 mbarrier 加 elect.sync 的单 kernel 融合、真循环。

4. 唯一的逃生舱：gdn.mma.tf32k8

必要性：NVVM 表列的 mma.sync m16n8k8 只有 f16/bf16/i8；nvgpu.mma.sync 的 verifier 强制 8×8×128b 基本片，tf32 封顶 K=4；反向的 fp32 GEMM 需要 fla 收割到的 tf32 m16n8k8 精确拼写。表内不可达属于 NVVM TableGen 的限制，与调度能力无关。工具链缺陷：经 inline asm 发射时，普通输出约束下 ptxas 将 D 四元组分配到同一条 mma 的 A 四元组上（读写重叠损坏操作数；整型探针 118/128 单元确定性失败），early-clobber 约束禁止重叠后消失——该缺陷对任何在 mma 上使用 inline asm 的实现成立。硬件探针：A-fragment 寄存器序为 row-half 外层，与 bf16 的 k-八元组配对直觉相反，由 16×8×8 整型探针在真机确认（tf32 精确表示整型，D = A·B + C 逐位成立；N(0,1) 输入偏差 4.2e-3 证实真 tf32 语义）。克制：tf32 按 24 个 fp32 GEMM 位点逐点数值验证，16 个放行（wy.u 位点误差 1.06e-2 超容差被否决；dhu 位点性能负收益整体回退），放行位点贡献所在阶段端到端 14.16→11.06 毫秒。预算 5 个、支出 1 个，支出的那一个带完整的必要性论证、缺陷定位与硬件探针。

十二、反向大形状的精度上界

反向小形状 1.72 倍、前向全形状超过 fla、冷启动全形状占优；u ≥ 1 的大形状为 0.41–0.49 倍。对该结果的结论是：

0.41–0.49 由误差容差合同决定，与实现质量无关。在 fla 的梯度容差（dq/dk/dv ≤ 8e-3、dβ/dg ≤ 2e-2）下，u ≥ 1 形状的 1.1 倍目标结构性不可达——理想执行的上限为 0.85–0.92 倍。

这里的"理想执行"按屋顶线模型（roofline，以标定带宽为唯一约束的执行时间下界）取 100% 利用率。该结论先于优化得出：CPU 字节定价器在 GPU 侧运行之前预测比值随 u 单调递减（边际每单位 u 2.67 倍、u ≥ 1 的所有形状都低于 1、小形状 2.17 倍是唯一超过基线的形状；终态优化将其深化到 1.72 倍），随后的阶梯实测精确验证。形状负载对性能比值的走向可以在编译期预测。

四类独立分析各自排除一条逃逸方向，松动任何一条其余仍成立。

1. 误差预算排除"把中间量降到 bf16"。反向链有 16 个 fp32 中间量候选，逐个做降精度测试：10 个可降、6 个被否决（合计 470 KiB 每兆行）。否决的原因值得展开：这些中间量存在大数相消——例如某量的真实量级为 O(0.1)，由若干 O(10) 的项相减得到；bf16 只有 7 位尾数，把 O(10) 的项各自舍入就引入 4.6e-2 至 6.9e-2 的绝对误差，恰好砸在被相消后的小值上，超出容差 2.4 至 11 倍。split-bf16 能提升乘积精度但节省不了存储流量（hi 与 lo 都要存）；dq、dk、dv 是被评分的输出，合同锁定 fp32。

2. 流量下界算术排除"把执行做到理想"。优化终态的字节流量下界约 0.75 毫秒每单位 u。屋顶线理想执行下 u=8 需 6.1–6.6 毫秒，对 fla 的 5.62 毫秒为 0.85–0.92 倍；即使整段删除三个最大 kernel（非真实选项）亦只到 0.88 倍。

3. 融合定价排除"删除 kernel 间数据搬运"。最后两个大 kernel（dqkwg 与 wyb）的融合被三重否定：可行最优共享内存池 97,024B，仅完美融合需求的 82%；单 CTA 占用反转实测 1.155–1.26 倍；u=8 净时间差最好、中位、最差为 +0.62、−0.11、−0.83 毫秒。即使不可实现的完美融合亦被字节算术限制在约 0.54 倍。结论 NO-GO。

4. 容差扫描排除"放宽容差合同"。dk 容差从 8e-3 放宽至 2e-2（2.5 倍）分四档测试，全部档位下没有任何被否决的中间量因此获得降精度资格（被否决符号的误差增量比最宽档还紧 6 倍）；首个解锁需放宽 8.2 倍；达到 1.1 倍需 dk 放宽约 15 倍且 dβ 放宽 2.4 倍两条轴同时进行，且全部解锁亦只将上界移至 1.08–1.15。容差的作用是阶跃的：达到特定档位之前，放宽不解锁任何符号。

四条合起来将 u ≥ 1 的 1.1 倍目标在合同层面封死；可改的输入（梯度容差、门控衰减设计、带宽标定）没有一项在编译器手里。全部核算可离线复算（仓库内三个定价脚本 tools/rc1_price.py、tools/r4_price.py、tools/tol_sweep.py），后两类分析的结论在不修改任何内核代码的情况下得出。

十三、对上游工具链的发现

以下发现对 MLIR 与 NVIDIA 工具链具有独立价值，每条均有探针或 SASS 级证据：

  1. workgroup 的 memref.alloc 被 stock 管线下译为设备端 malloc，真机全部非法地址错误；修复方案在 gdn_smem_fix.py。
  2. transform 的 create_async_groups 在每组后立即插入 wait_group 0，异步复制结构性无法重叠。
  3. block-uniform 的 staging 被每线程重复执行（256 次冗余复制）。
  4. ptxas-blackwell 忽略 --maxrregcount、遵循 PTX 源内 .maxnreg；ptxas -v 报告只对应第一次编译，资源对账以第二次为准。
  5. cp.async 到 ldmatrix 的静默数据损坏：经 ld.shared 读回正确、经 ldmatrix 读回错误，仅影响与构建调度相关的行块子集；st.shared 安全。
  6. ptxas 跨入口静默合并重名 .shared 符号，产生越界写。
  7. 模块加载顺序效应：加载顺序决定 .global 布局，访存最重 kernel 出现约 6% 系统偏差，顺序互换偏差精确反号。
  8. 分离进程的绝对时延在零负载下仍随时钟状态漂移（实测同一 cubin 可相差 47%）。
  9. sm_120 线程块簇大于 1 可用（设备验证，推翻只有 1×1×1 的通行假设）；簇属性本身零开销，跨 CTA 数据交换的 57 微秒成本决定其收益。
  10. cp.async 的 wait_group 为每线程语义，跨 warp 可见性需要显式栅栏。
  11. tf32 m16n8k8 的 inline-asm 发射：early-clobber 为正确性必要条件；A-fragment 寄存器序为 row-half-outer，与 bf16 直觉相反。

十四、复现、相关工作与血统

仓库结构：方言与 pass 在 dialect/；全部生成器、求解器、成本模型、后处理与测量 harness 在 tools/；幂等驱动脚本在 scripts/；每个里程碑的报告与原始数据在 evidence/G0 至 G7；深挖论文（11 章）在 paper/zh。复现入口 make repro-g1 至 repro-g6 逐门验证（语义三方闭合 15 分钟纯 CPU；旋钮矩阵 25 分钟纯 CPU；标定与排序门槛 45 分钟两步 GPU；逐配置正确性 1 小时 GPU；全算子验证加交错终判 1 至 1.5 小时 GPU；搜索成本 10 分钟），make repro-all 顺序执行、首败即停。环境需求：WSL2、conda 环境 gdn、CUDA 13.x、计算能力 12 以上 GPU；语义与求解部分完全纯 CPU。

相关工作定位：fla 为性能基线与覆盖合同一方；FlashQLA 为覆盖合同另一方与 sm_120 前向现役最快；TileLang 的 z3 调度器只存在于 Ascend 后端，其 CUDA 侧空白即本项目移植点的来源；XLA/TPU 为哲学对标的四支柱；CAKE 以 agent 写 IR，本项目以约束求解替代 agent 迭代；FlexLA、Hexcute、TileLoom 一系的调度均不由 IR 承载。血统交代：编译期求解的机制来自 TileLang 的 Ascend 实践，本项目将其上移一层——决策变量从指令时槽改为旋钮向量，此移植在 CUDA 侧无先例。

参考实现 fla 与 FlashQLA 均为 MIT 许可，在本项目中仅作对照基准使用，其 PTX 收割物不含其源码。
