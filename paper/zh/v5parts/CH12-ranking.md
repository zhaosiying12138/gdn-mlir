## 十二、排序质量的度量：Spearman 与搜索成本

一个排序模型交货时必须回答两个问题：排出的次序有多准；用它在编译期完成排序，比把候选搬上 GPU 逐个实测便宜多少。前者是模型的质检，后者是它存在的经济理由，合起来构成编译期调度的完整收益陈述——便宜，且准到够用。术语先行：秩指一组数按大小排序后各自的名次；Spearman 秩相关（下文记 ρ）先把预测值与实测值各自换成名次，再对名次做普通相关，度量两组数在排序意义下的一致程度。

### 1. 为什么度量停在秩这一层

三条理由各自独立成立。其一，消费方式是次序：求解器枚举全部合法配置后按预测时延排序、取头部送编译与实测，绝对数值从不直接使用。其二，绝对时延在测量学上不可靠：同一 cubin 在分离进程、零负载下仍随时钟状态漂移，两个进程可相差 47%，测量纪律因此只信任同窗交错的成对比值，把绝对毫秒数降为工程参考（主文第十节）。其三，模型有已记录的均匀缩放偏差（mma 路径整体低估 3–5 倍，见第三节盲区清单），保序缩放不伤次序。Spearman 对任何严格单调增的变换不变，恰好同时容纳这三条：它度量的正是保序性，且仅是保序性。

实现不引入统计库依赖：纯算术、无随机数、平局取平均秩且平局规则固定——这是确定性契约的一部分，排序可复现，验证同样可复现：

```python
def spearman(xs, ys):
    """Pearson correlation of average ranks (tie-safe)."""
    n = len(xs)
    if n < 2:
        return float("nan")
    rx, ry = _ranks(xs), _ranks(ys)
    mx, my = sum(rx) / n, sum(ry) / n
    num = sum((a - mx) * (b - my) for a, b in zip(rx, ry))
    den = math.sqrt(sum((a - mx) ** 2 for a in rx)
                    * sum((b - my) ** 2 for b in ry))
    return num / den if den else float("nan")
```
［tools/gdn_costmodel.py:763-773，逐字；_ranks 的平均秩实现 748-760 行］

配套一个运维口径 topk_overlap：预测与实测各自最快的 k 个配置的交集占比（k 取 5，tools/gdn_costmodel.py:776-781）。秩相关回答整体次序，重叠度回答头部是否可用——排序系统的下游只消费头部。

### 2. 验证设计：n=18 的构成、分阶段与门槛

被测集合的构成决定结论的效力。20 个编译配置中 18 个取得有效实测，两个被状态过滤器排除且原因落盘：warpspec 配置在硬件上 mbarrier 死锁（TIMEOUT），tma 配置的 cubin 不含数据全局（NOT_TIMED，CUtensorMap 接线属运行时契约）［evidence/G3/validation.json:6-15］。18 个的构成：kkt 阶段 10 个——mma 7 个，覆盖流水深度 p0/p2/p3、warp 数 2/4/8、三种 tile；nomma 3 个——外加 o 阶段 6 个（bf16 与 f32、mma 与 nomma、两组 K/V 维度）和 2 个参考锚（单 m16n8k16 原子核与 ldmatrix 版）。实测口径：静态共享内存修复后的零参 cubin，CUDA 事件 50 次取中位。验证程序逐形式计算整体与分阶段 ρ 及 top-5 重叠，并对门槛给出裁决：

```python
for f in forms:
    rho = cm.spearman(preds[f], measured)
    ...
    per_stage[st] = (cm.spearman(xs, ys) if len(xs) >= 3 else None)
    report["forms"][f] = {"spearman": rho,
                          "spearman_per_stage": per_stage,
                          "top5_overlap": cm.topk_overlap(preds[f], measured, 5)}
best = max(forms, key=lambda f: report["forms"][f]["spearman"])
report["verdict"] = ("PASS" if report["forms"][best]["spearman"] >= gate
                     else "FAIL")
```
［tools/gdn_solver.py:487-502，节选；门槛 gate=0.7 为契约值，样本少于 3 的阶段不单独打分］

结果：v2 整体 ρ 0.8962，kkt 阶段 0.936（n=10），o 阶段 0.829（n=6），top-5 重叠 0.8（五分之四），门槛 0.7，裁决 PASS［evidence/G3/validation.json:41-72］。分阶段单独报告的用意：kkt 与 o 是两个独立的 kernel 家族，合并报告会让一个家族的强势掩盖另一个的弱点。门槛本身留了容差——排序系统的职责是把好配置送进头部，最终选择另有逐配置 GPU 对照兜底，门槛无须逼近 1。另一条如实记录：v3 在单 chunk 基准上与 v2 秩相同（波次为 1，数值一致），全形状下 v2 与 v3 的头部翻转（小 tile 对大 tile）是占用项起作用的模型预测，属待上机抽查项，单 chunk 验证数据区分不了两者。

### 3. 稳健性与已知盲区

门槛通过之后还要回答：结论对测量噪声与常数误差有多敏感。两组扰动实验各 200 次注入。其一，全部结构常数（每 MAC 周期数、tf32 折算比、LSU 发射率、溢出带宽份额、张量每时钟吞吐）各正负两倍缩放：ρ 稳定在 0.882 至 0.902。其二，对实测时间加均匀噪声正负 5/10/20/30%：ρ 中位依次 0.896、0.890、0.885、0.885，最差的第五百分位 0.856——比观测到的运行间散布（kkt p2 w4 为 21.0±0.3 µs）大近一个量级的噪声下门槛仍通过［evidence/G3/solver_report.md §4］。结论：PASS 裁决并非共载窗口的伪影。

盲区清单逐条文档化，共同特征为方向正确、幅度未建模：

其一，mma 路径绝对值系统性低估 3–5 倍（片段装载依赖链、超出 7.707 ns 边际成本的栅栏往返等延迟主导效应）——对所有 mma 配置近似均匀缩放，秩不受影响。其二，p0 的 .ca 串行化幅度：同 tile 同 warp 数下实测 kkt p0 为 105 µs、p2 为 21 µs（5 倍差），模型只预测 7.4 µs；排序方向正确（p0 在流水变体中垫底），幅度未建模——编译期推不出 .ca 惩罚常数，对着实测时间拟合一个常数被零拟合契约否决。其三，共享内存带宽可能被广播膨胀（均匀地址基准的固有风险），只影响占比不超过 1% 的 T_smem 项。其四，o 阶段 strided-B 变体每 MAC 实付代价约为模型的 2 倍（簇内不精确，方向一致，已接受）［evidence/G3/solver_report.md §2 盲区一节］。

### 4. 搜索成本：0.8 秒纯 CPU 对 39.81 秒上机

编译期排序的经济账在同一证据树里测齐。本方：kkt 空间 368 个合法配置，Z3 枚举 0.307 秒、含全排序的完整求解 0.378 秒；o 空间 465 个配置 0.444 秒；两阶段合计约 0.8 秒，全部在 CPU 上，GPU 秒为零——首选候选上机之前，GPU 未被搜索触碰［evidence/G6/scratch/solver_timing_summary.json］。fla（Triton 运行时 autotune）：首次调用前向 16.55 秒（25 个候选配置跨 5 个 kernel 逐个编译、上机、计时），反向 23.26 秒（23 个候选跨 4 个 kernel），合计 39.81 秒设备时间、48 个配置；其磁盘配置缓存默认关闭（FLA_CACHE_MODE 未设即 DISABLED），代价按进程与按形状键重复支付［evidence/G6/search_cost.md §b；fla_autotune_cost.json］。
