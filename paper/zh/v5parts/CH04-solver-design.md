## 四、把 autotune 变成求解器：动机与总体设计

本章与后续五章讲同一份源码：tools/gdn_solver.py，661 行，含命令行与自检。它的职责在编译器总览里只占一句话——为给定形状求出全部合法的旋钮组合并按预测时间排序——但这一句是整个 L2 调度层的心脏。手写内核把调度决策固化在源码里（FlashQLA 的 warp 专化调度即手写成果），Triton 系把决策推迟到运行时（fla 每形状首次搜索需 39.8 秒设备时间，48 个配置逐个上机）。两条路线各有代价：前者每换一个形状、每加一个算子都要重新手写，后者的搜索开销与冷启动由每个部署进程反复支付。第三条路线把"哪些旋钮组合合法"表述为一个约束可满足性问题，在编译期求解、在编译期排序、在编译期产出工件。第二十二到二十六章按建模、约束、枚举、防御、复现五个侧面把源码读完。

术语先立三条。Z3 是一个 SMT 求解器；SMT（Satisfiability Modulo Theories，模理论可满足性）在布尔可满足性问题（SAT）之上叠加整数算术、布尔量等理论的可满足判定，z3py 是它的 Python 前端。旋钮向量指十维离散决策变量——数据类型、精度、tile 三个维度、warp 数、流水深度、mma 开关、warp 专化、TMA——即第二十一章 transform 工件的参数化自由度。合法指同时满足耦合、结构与资源三类约束（第六章）。

### 1. 哲学的移植与两问

第一章表 1 对标的哲学是 XLA 在 TPU 上的调度组织：调度决策全部在编译期做出、编译产物不携带运行时搜索、每层 IR 独立可验证。把这套哲学移植到原生 MLIR、消费级 Blackwell、单算子族上，在写任何求解代码之前必须先回答两问，且两问都不关于求解器本身。

第一问，凭什么排序。求解器只判定合法性，"哪个合法配置更快"由成本模型回答；若成本模型不可靠，全空间枚举只是把错误的排序做得更全面。本项目的答案先行验证：零自由常数的校准解析成本模型，对 18 个实测配置的 Spearman 秩相关 0.8962（门槛 0.7），全部结构常数扰动正负两倍后秩相关仍在 0.882–0.902（第十二章）。第二问，凭什么相信。求解出的配置要真的编译、真的装载、真的算对，这由验证塔把关：L2 出口有 ptxas 静态资源复核（第二十九章），L3 逐配置对 fp64 参考，L4 交错终判（第三十七章）。

两问的答案塑造了求解器的形态：职责三分——合法性归 Z3，优劣归成本模型，正确性归验证塔。求解器因此可以很小且全部可读，它的每个输出在下游都有一道独立关卡复核。

### 2. 为什么是 Z3

合法性问题的形状决定工具。约束是异构的：整除性（tile 对齐写成整除断言）、布尔蕴涵（TMA 的启用蕴含 warp 专化）、资源不等式（共享内存字节数不超过容量），并且资源项本身按布尔旋钮分岔——mma 开关在两套字节公式中选一套。这类整数、布尔与条件算术的混合组合约束正是 SMT 求解器的原生工作负载：约束写成符号断言交给求解器，可满足性的判定与满足指派的提取都由它完成。若以嵌套循环手写合法性过滤，耦合与资源约束会摊进多层循环条件里，每加一条约束都要改动循环结构；写成断言列表后，加一条约束只是加一行 s.add，且每行与文档逐条对应（第一章章节地图所称的"约束即代码"）。Z3 还自带枚举机制：对已产出的解追加一条阻塞子句，下一次判定即给出新解，全空间穷尽有现成的循环写法（第七章）。

### 3. 上移一层：从指令时槽到旋钮向量

这套机制的血统来自 TileLang。TileLang 自带一个 z3 调度器，但它只存在于 Ascend 后端，CUDA 侧退化为运行时搜索。它的机制是模调度（modulo scheduling，软件流水的经典构造）：决策变量是每条指令的发射时槽，求解器在依赖与资源约束下最小化启动间距（II，initiation interval），由延迟估计引导对 II 做二分搜索。本项目移植该机制并上移一层：决策变量从"每条指令何时发射"改为"这份内核用哪组旋钮"。源码头部的自述：

```
GDN Z3 knob solver (G3-B): TileLang z3_scheduler mechanism ported to
CUDA/sm_120 - v1 form: SMT enumeration/ordering of the DISCRETE KNOB
SPACE (not instruction start-time scheduling yet).

  objective   : minimize the calibrated analytical cost model
    (tools/gdn_costmodel.py). The cost model is non-linear
    (max/blend, divisions), so v1 enumerates every legal knob
    assignment with Z3 (SAT + blocking clauses) and ranks
    outside the solver - same role as TileLang's
    estimate_latency-guided II binary search, one level up.
```
［tools/gdn_solver.py:1-4、14-19，模块 docstring 节选，机制与目标两段］

上移一层带来两个直接后果。其一，解即工件参数：旋钮向量经一次字典翻译即成 transform 工件的 factor、depth、tile_sizes 与发射几何（第五、二十一章），流水线里没有指令调度器这个部件，指令级编排由 NVVM 管线与生成器模板承担。其二，问题规模塌缩：变量十个、每维取值个位数，合法空间只有数百个点，穷尽枚举在亚秒级完成，"求解"从搜索问题变成枚举问题。

### 4. 总体数据流

求解器坐在一条单向流水的中段，源码 docstring 把下游记作回环（loopback）：solve 之后，Top-K 配置交 gdn_l2_gen.py 生成并编译（scripts/run_l2.sh 驱动），ptxas -v 做静态资源复核，再用实测的编译期特征重排，幸存者进窗口计时（23-26 行）。各站与承载：

表 21-1：求解回环
| 站 | 做什么 | 承载 |
|---|---|---|
| 建模 | 声明十维变量与域 | KnobSpace 构造器（第五章） |
| 约束 | 耦合、结构、资源三类断言 | 同上（第六章） |
| 枚举 | 全空间穷尽、记录结束态 | enumerate（第七章） |
| 排序 | 成本模型预测、终排序键定序 | gdn_costmodel 与 solve（第七章、第十一章） |
| 实例化 | Top-K 配置生成工件与 cubin | gdn_l2_gen.py 与 run_l2.sh |
| 复核与计时 | 资源包络对账、窗口裁决 | ptxas -v（第二十九章）、交错终判（第三十七章） |

kkt 阶段合法空间 368 个配置，枚举 0.29 秒；o 阶段 465 个配置，0.33 秒。两个数字的含义分开读：368 与 465 说明空间小到可以穷尽——穷尽给出完备性，排名覆盖每一个合法点；0.29 与 0.33 说明穷尽快到可以放在编译期——合进标定读取与成本模型计算，整条新形状调度 0.8 秒纯 CPU、GPU 时间为零，对照 fla 首搜 39.8 秒设备时间。穷尽的收尾是一个可机查的凭证：最后一次判定返回 unsat，即"再无未枚举的合法点"（第七章）；这份凭证随输出落盘（第九章）。
