## 三、为什么这个算子值得一个编译器

这个算子凭什么值得一条专门的编译管线？答案有两半。前一半是数学：GDN 的递推在 chunk 化之后暴露出三角性、仿射性、双侧掩蔽三重结构，结构精巧且随形状、精度位点、内存布局大幅变化，任何一份手写内核都只覆盖这片变化空间的一个小角落。后一半是工程：手写路线把调度知识锁死在内核源码里，每换一个形状或算子就要重新手写一遍，且调度决策被推迟到运行时。本章的数学是第十三至二十三章 L1 展开的全部依据。

### 1. 算子与递推四步契约

Gated DeltaNet 对每个 token 维护一个 K×V 的状态矩阵 h，并按固定顺序递推（g ≤ 0，β ∈ (0,1)）：

```
h ← 2^g · h                （衰减在先）
b ← β ⊙ (v − k·h)          （delta 修正项）
h ← h + kᵀ ⊗ b             （外积写回）
o ← q · h
```

术语先定义：k 为键向量（经 L2 归一化），v 为值向量，q 为查询向量，g 为门控（衰减的对数，非正），β 为门，b 为 delta 修正项，o 为输出。四步的顺序不可交换，属于语义契约：衰减必须先于写回，修正项读取的必须是已衰减的状态。这一契约正是 L0 verifier 所固定的数值约定，也是第二章全部梯度的被微分对象。直接按扫描实现意味着每个 token 读写一遍 K×V 状态——状态搬运随序列长度线性堆积，带宽不可承受。

### 2. chunk 仿射性：从扫描到矩阵乘的枢纽

chunk（分块）指把序列切成定长段落（长度即 L0 的 chunk_size 旋钮，如 64）。chunk 化的关键观察是：一个 chunk 内 C 步递推对状态构成一个仿射映射——状态的新值是其旧值的线性函数，加一个不依赖旧状态的项。线性部分可以并入矩阵乘，常数部分并入向量乘，C 步顺序依赖折叠成一次批量计算。这是从扫描到矩阵乘的转换枢纽：扫描按 token 串行地触碰状态，矩阵乘按 chunk 整块地触碰状态，访存量相差一个 chunk 长度的因子。chunk 化及其后的全部代数整理都是精确恒等式，不含近似步骤——第十三至二十三章的三方交叉验证正是以 fp64 核对这份精确性。chunk 化后的核心是三个对象。

### 3. 对象一：KKT 矩阵与前代换

直觉是联立方程。chunk 内每个 token 的修正项 b_i 依赖当时的状态，而状态又依赖同一 chunk 内更早 token 的修正——与其逐个代入，把 C 个相互依赖的方程联立求解。因果性决定了解的结构：每个 token 只依赖更早的 token，方程组因此是下三角线性系统。该系统就是 KKT 矩阵 A = strict_tril( β ⊙ (k·kᵀ) ⊙ 2^(gc_i−gc_j) )：strict_tril 取严格下三角（对角线归零），gc 为 chunk 内累计门控，i、j 为 token 在 chunk 内的时间序号——衰减因子 2^(gc_i−gc_j) 恰好把两步之间的门控差折进内积。A 严格下三角，I+A 为单位下三角，其逆 T = (I+A)^(−1) 由前代换求得：按时间顺序逐行求解，无主元选取、无除法。

数值稳定性有三个结构性来源：键向量经 L2 归一化使内积不超过 1、β ∈ (0,1)、衰减因子单调不超过 1。三者合起来约束了下三角系统的范数，前代换因此天生稳定。

### 4. 对象二与对象三：跨 chunk 递推与输出分解

跨 chunk 的状态递推 S′ = (2^gcl·I − k̃ᵀw)·S + k̃ᵀu 仍是仿射形式（S 为入口状态，gcl 为 chunk 级累计门控，k̃、w、u 为 chunk 内修正项聚合出的矩阵与向量，其构造在 L1 展开章逐项给出）。它的价值在于衰减的折叠方式：衰减只通过状态上的 2^gcl 与键行上的 2^(gcl−gc) 两个显式因子进入，每个 chunk 将整段历史衰减折叠为对入口状态的一次乘法——任意长的历史都无需回放。输出分解 o = o_intra + o_inter 把应答拆成 chunk 内贡献（由本 chunk 的修正项直接给出）与跨 chunk 贡献（由入口状态携带）两部分，两部分都能落成矩阵乘。至此，整条前向由若干次矩阵乘与逐 chunk 的仿射递推构成，全部可上张量核。

### 5. 反向最微妙的一步：dA 双侧掩蔽

前向三对象的对偶物构成反向传播。最微妙的一步是 dA 的收缩。A 出现在 T 的定义里，梯度回传到 A 时，单侧近似会重复计数直达项并丢失交叉项——在 C=3 的最小反例上，单侧近似在符号层面被否定：展开三步递推即可看到漏项，连数值实验都不必做。正确形式为双侧掩蔽收缩 dA = −strict_tril( Tᵀ · strict_tril(G) · Tᵀ )，与 fla 的 prepare_wy_repr_bwd 等价。"双侧"的含义：左右两次 Tᵀ 各携带一次掩蔽，直达项与交叉项各计一次。这一步在最终反向链的 wyb kernel 中执行，产出最终的 dk、dβ、dg、dv；它是反向链正确性的分水岭，也是第三十七章容差合同的数学基础之一。

### 6. 现状：手写内核的两个结构性代价

这个算子目前由手写内核服务。fla 基于 Triton，运行时 autotune，每形状首次搜索需要 39.8 秒设备时间；FlashQLA 基于 TileLang，手写 warp 专化调度；TileLang 自身的 z3 调度器只存在于 Ascend 后端，CUDA 侧退化为运行时搜索。手写路线有两个结构性代价。其一，调度知识不可组合：每个新形状与新算子需要重新手写，本章的三个数学对象在每个内核里重新实现一遍，KKT、前代换、双侧掩蔽的知识无法复用。其二，调度决策推迟到运行时，产生冷启动与部署开销——第二章的冷启动表已给出量级（fla 每形状首搜 39.8 秒设备时间，缓存命中后仍需 0.65–5.67 秒）。

| 实现 | 栈 | 调度方式 | 每形状首次代价 |
|---|---|---|---|
| fla | Triton | 运行时 autotune | 39.8 s 设备时间 |
| FlashQLA | TileLang | 手写 warp 专化 | 手写内核成本 |
| 本编译器 | stock MLIR | 编译期 Z3 加成本模型 | 0.8 s 纯 CPU |

### 7. 本编译器的回答：调度即 IR

本编译器把调度从内核源码中抽出，变成编译期可求解的问题，四件事各就其位：调度以 IR 表达（transform dialect 参数化工件与方言属性承载全部旋钮），合法性由 Z3 判定，优劣由校准解析成本模型排序，正确性由分层验证把关。参考实现由此成为旋钮空间中的坐标：fla 的多级流水加 cp.async 加寄存器顶格，与 FlashQLA 的 warp 专化加 TMA 加单 kernel 融合，是十维旋钮空间中的两个极端配置——复现一个参考实现的工作从重写内核变成调参。

本章三个数学对象之所以支撑得起这套回答，在于其全部结构都能被 IR 与求解框架显式承载：三角性落在 L1 的掩蔽控制流里，仿射性落在矩阵乘与递推的边界划分里，双侧掩蔽落在反向链的收缩步骤里；形状、精度位点、内存布局的变化则全部交给旋钮空间。数学对象如何在 L1 落成逐行可执行的 IR，第十三章起展开。
