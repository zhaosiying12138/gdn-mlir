## 三十七、容差合同与测量口径

验证塔上还有两份合同没有展开：数值侧的容差合同（多大算对）与性能侧的测量口径（多快算快）。两份合同的共同点是先例性——都先于测量被定下，测量只负责在合同框架内出数。术语先行：容差合同，指对每个输出张量规定的最大允许绝对误差；标定，指用实测数据为合同数字找依据的过程；交错终判，指本方与基线在同一进程、同一位相同输入上交替成对计时的协议。

### 1. 容差合同的设计：定在 fla 自身距离的量级

合同的问题意识：本编译器的数值主张是与 fla 同级准确，那么"同级"必须可定义。把门定得过紧，等于要求超过 fla——一个自身残差就有 2.57e-2 的基线，门却定在 8e-3，任何对照都失去意义；定得过松，验证又失去分辨力，真实缺陷会混进门的阴影里。解法是把门定在 fla 自身对 fp64 参考的距离量级上——fla 自己离参考多远，本方的合法活动范围就有多大。这个定义还有一层好处：它把数值主张与性能主张解耦，性能竞争（第二章）与数值达标（本章）各自有独立的判据，互不背书。三档门限：

| 输出 | 门限 |
|---|---|
| o 与 ht | 5e-3 |
| dq、dk、dv、dh0 | 8e-3 |
| dβ 与 dg | 2e-2 |

dβ 与 dg 一档放宽 2.5 倍有其原因：标定数据显示 fla 自己的 dβ 残差就已越过 8e-3 这条线（小形状 2.57e-2、中形状 1.78e-2、大形状 2.10e-2），若按 8e-3 定门，被评分的基线自己都不及格，合同失去"同级"语义；2e-2 一档恰好覆盖 fla 的可达域。门的宽窄由此从拍脑袋变成有标定依据的量。

### 2. fla 标定：残差即 bf16 舍入

标定的方法：对每个输出张量，取 fla 对 fp64 JAX 参考的最大绝对误差，除以该输出 dtype 的 bf16 舍入下界（参考值最大绝对量级乘 bf16 量化台阶）。比值接近 1 意味着 fla 的误差基本就是输出量化的必然代价；远大于 1 才说明实现额外引入误差。原始记录一例（大形状的 dg）：

```
"dg": {
  "fla_dtype": "torch.float32",
  "max_abs_err": 0.02581325795185463,
  "ref_max_abs": 3.7026142737449854,
  "rel_err": 0.0069716303247937235,
  "bf16_out_floor": 0.005954688964605381
}
```
［evidence/G5/refs/tolerances.json，cases.rc1_B1T16384H16.fla_vs_jax.dg；同一文件覆盖三个形状乘八个输出共 24 组记录］

全套 24 组的标定结论：fla 的残差系统性落在其输出 dtype 的 bf16 舍入下界的约 2 倍（1.36–4.33 倍，中位 1.9 倍）——即 fla 的残差基本就是 bf16 舍入，实现性误差只占小头。这组数字同时背书了合同档位的合理性：门限定在"舍入下界的两三倍"这一量级，恰好是"与 fla 同级"的可达域。

### 4. 交错终判协议

性能侧的合同。协议内容：同一 GPU 窗口、同一进程内，本方与基线在同一位相同的输入上交替成对计时，每形状 30 对；点估计取逐对比值的中位数（对离群对稳健），显著性由精确符号检验给出。符号检验的实现即展品——胜负计数加精确二项尾概率，无 scipy 依赖：

```
def sign_test_p(ratios, ref=1.0):
    """Exact two-sided sign-test p for median(ratios) == ref.

    Wins/losses vs ref (ties dropped); p = 2 * P(Bin(n, .5) <= min(w,
    n-w)), capped at 1.  Exact for n <= ~20 (pairs here are 5-30); no
    scipy dependency.  None if every pair is a tie.
    """
    wins = sum(1 for r in ratios if r > ref)
    losses = sum(1 for r in ratios if r < ref)
    n = wins + losses
    if n == 0:
        return None
    k = min(wins, losses)
    p_lt = sum(math.comb(n, i) for i in range(k + 1)) / 2.0 ** n
    return round(min(1.0, 2.0 * p_lt), 6)
```
［tools/gdn_final_adjudicate.py:80-94，逐字；同文件 97-126 行给出中位数、四分位距与可判性规则的配套实现］

30 对的采样量由检验力倒推：30 对全胜时 p 约 1.9e-9，足以支撑九章级结论；5 对的地板只有 0.0625，因此正式裁决一律用 30 对。真实出样（共载窗口、B1T8192）：30 对、逐对比值中位 1.3307、四分位距 0.2363、符号检验 p 值报 0.0［evidence/G5/final_adjudicate_r25f_w32p.json，results.B1T8192.stats；同一 JSON 同时落盘窗口前后 nvidia-smi 快照与双侧原始样本各 30 个］。协议另配一条数量级可判性规则——效应量超过四分位距相对值三倍才在脏窗口下表态，边缘情形一律交由空闲窗口复测。这条规则的克制有真实案例：一次共载 hostile 窗口中 B1T2048 的比值中位数看起来有 2.3 倍，但逐对四分位距相对值 0.31、首对双方同时被共载作业打爆，规则拒绝表态——协议在窗口撑不起结论时选择沉默，宁可等待复测［evidence/G5/adjudication_methodology.md，worked example 一节］。

### 5. 两条实测依据：绝对时延为什么不可信

协议的每一条设计都有实测反例支撑。第一条，分离进程的绝对时延在零负载下仍随时钟状态漂移：同一 cubin、相隔数分钟的两个进程，fla 前向 B4T2048 一侧 0.9240 毫秒、另一侧 1.3617 毫秒，相差 47%——原因是进程间隙的空闲降频（nvidia-smi 快照捕捉到步骤间 180–712 MHz 对步内 1590+ MHz 的时钟摆动）［evidence/G5/GATE_REPORT_FULL_REMEASURE.md:127-135］。第二条，同进程内模块加载顺序改变全局内存布局：谁第二个经模块装载认领全局区，谁就在访存最重的 kernel（约 160MB 工作集）上多付约 6%，且单独翻转构建顺序可使偏差精确反号（+14.8 对 −16.8 微秒，各 40 次中 39/40 与 0/40）［evidence/G5/fwd_report.md:2018-2027］。结论落地为守则：加速比的分母一律取同窗交错测得的基线，绝对毫秒数只作工程参考。

### 6. 共载与空闲双窗口

测量窗口分两类并分别报告：共载窗口（测量时 GPU 上常驻其它计算任务）与空闲窗口（无其它任务）。双窗口的必要性来自结论的可解释性：共载把双方都压离理想时钟，fla 的 kernel 体积更大、受压更深，因此共载比值系统性偏高（前向 B1T2048 共载 2.125 倍、空闲 1.611 倍）；空闲窗口把双方放回理想状态，B1T8192 相应回到 0.991 的持平档。两个窗口各答一个问题——共载答"生产环境混部下谁快"，空闲答"硬件理想态下谁快"——把两组数字并列报告，比只报其中一组更接近事实。
