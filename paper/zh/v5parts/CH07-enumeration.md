## 七、SAT 与阻塞子句：全空间确定性枚举

建模与约束定义了合法空间，枚举把它物化成一张完整清单。枚举的目标在函数 docstring 里写死：确定性顺序、完整覆盖、结束态可查。三个目标分别由三段机制承担——固定声明序（第五章）、阻塞子句循环、last_check 记录。

术语先立。可满足（satisfiable，sat）指存在一组变量指派使全部断言成立；不可满足（unsat）指证明不存在这样的指派；求解模型（model）指一个具体的满足指派，注意它与成本模型是两个词。

### 1. check、model 与三态语义

z3py 交互的核心是两个调用。Solver.check() 对当前断言集做一次可满足性判定，返回三个值之一：sat，存在满足全部断派的指派；unsat，已证明不存在；unknown，求解器放弃——资源限额耗尽、问题落入判定能力之外的片段等。三态的认识论地位并不对等：sat 与 unsat 是证明，unknown 只是承认。一个返回 unsat 的求解器等于出具了"无解"的数学凭证；一个返回 unknown 的求解器什么都没证明。这个不对称在第八章变成一整章的防御性设计——unknown 绝不能与 unsat 混同处理。

check 返回 sat 后，Solver.model() 取出一个满足指派。model 里的变量经 m[var] 读回取值，但 model 的契约只保证"足以证明 sat 的那部分指派"，被其余指派唯一决定的变量可能缺席——读回 None。这是 partial model 现象，第八章展开其成因与补全。枚举循环先把这两件事做成一台引擎。

### 2. 为什么把排序放在求解器外

z3 提供优化接口 Optimize，可对目标函数求最小值，表面上正合"挑最快配置"的需求。本方案放弃它，理由记录在模块头部：成本模型是非线性的——项间取最大值、做混合、做除法（docstring 15-16 行）。把这样的目标压进 SMT 优化器，等于在非线性目标上做优化搜索，其完备性与行为可预期性都弱于纯判定问题。何况约束侧的字节模型本身已含变量乘变量（bt 乘 bk），这类非线性整数算术 z3 只能不完全地处理，判定尚有返回 unknown 的风险（第八章的防御正为此设），优化问题在此之上更甚。枚举加外排序的分工因此干净：求解器只回答"哪些合法"——每次一个纯判定问题；排序留在 Python 里逐项可审计，且每个配置的分解项（terms_ms）本来就要作为证据随排名输出。求解器与成本模型各司其职，中间的接口是一张完整清单。

### 3. 阻塞子句：强制新解

枚举循环（继承展品）：

```
while len(out) < limit:
    r = s.check()
    if r != z3.sat:
        self.last_check = str(r)      # "unsat" = 空间干净穷尽
        break
    m = s.model()
    # ……读取/补全各旋钮值……
    out.append(vals)
    block = [self.v[k] != z3.IntVal(v) for k, v in vals.items()]
    s.add(z3.Or(block))               # 阻塞子句：下一解必须不同
```
［tools/gdn_solver.py:230-235、253-257，中间为模型读取与补全（继承展品，两段合排）；真实代码对布尔旋钮用 z3.BoolVal 构造不等项，254-256 行］

阻塞子句（blocking clause）的含义：对刚产出的向量 vals 的每一维写一个"不等于当前值"，再把全部不等项用 Or 连接后加入断言集。它的语义是"下一个解至少有一维与这个不同"——已产出的向量被整体排除，任何仍满足原约束加全部阻塞子句的指派必然是没见过的新向量。循环体每轮做三件事：check 判定、model 取解加读取补全、block 排除刚产出的解。同一向量不可能重复出现，因为它的阻塞子句永远在场；当全部合法向量都被阻塞后，check 返回 unsat，循环以穷尽告终。limit 参数（默认十万）是防御性护栏：清单长度超限时循环退出，此时结束态既非穷尽也非限额中断，由调用方检视。

模型读取段（236-252 行）按声明序逐维读值：整数维经 val.as_long() 转 Python 整数，布尔维经 is_true/is_false 判定，缺席的维度进入补全路径（第八章）。读取与补全的次序也是固定的：先用一遍循环收集全部缺席键，再按声明序逐个补全（250-252 行）——即使多个维度同时缺席，补全的先后也不依赖字典遍历的任何偶然。读取与补全全部结束后才构造阻塞子句——子句从补全后的 Python 值构造，绝无直接使用读回的 None；每轮的模型数、缺席数、补全数都累进 enum_stats（228-229 行），防御路径的触发量随输出可查。

### 4. 穷尽优于启发式，unsat 作为穷尽凭证

这个空间只有数百个点——kkt 阶段 368 个、o 阶段 465 个——穷尽枚举分别用时 0.29 与 0.33 秒。在这个量级上，穷尽对启发式有压倒优势。启发式采样（挑一部分候选评估）省下的时间不足一秒，付出的代价是完备性：排名只覆盖样本，"更优配置落在未采样处"的可能性无法排除，且没有任何事后手段能区分"采样足够"与"恰好漏掉最优"。穷尽枚举的排名覆盖每一个合法点，完备性由求解器的返回值背书。

这个背书是机器可查的。枚举如何结束被记录在 last_check 字段：循环因 r != sat 退出时，str(r) 存入——"unsat"意味着在全部约束加全部阻塞子句之下不存在任何指派，即空间已干净穷尽，这是求解器出具的证明；"unknown"则意味着判定被资源限额中断，空间只是被截断（第八章）。输出 JSON 把 last_check 随 seed、rlimit、enum_stats（模型数、partial model 数、补全次数）一并落盘（403-406 行）：复核者不重跑就能看到穷尽凭证，重跑则应当得到逐字节相同的结果（第九章）。

枚举清单的最终顺序由排序键定（新展品）：

```
ranked.sort(key=lambda r: (round(r["predicted_ms"], 12), r["name"]))
for i, r in enumerate(ranked):
    r["rank"] = i + 1
```
［tools/gdn_solver.py:393-395，逐字；predicted_ms 为成本模型预测的毫秒数（388 行）］

排序键是一个两元组：预测毫秒先四舍五入到 12 位小数——两个预测值相差一千万分之一毫秒纯属浮点尾噪，视为并列；并列者按配置规范名的字母序决胜。排序因此构成全序且确定：输出顺序与求解器给出模型的顺序完全解耦，即使枚举顺序有变，排名文件不变。这行代码是第九章确定性总账的收口一环。
