## 十七、观察 IR：调试与验证工具箱

渐进式下降的每一层都可能出错，而 MLIR 相比于黑盒编译器最大的工程优势在于：每一层的产物都是可观察、可验证的文本。本项目的调试与验证工具大多不出现在最终论文的贡献清单里，但没有它们，五层下降中的任何一个环节出错都无法定位。

### 1. gdn-opt 与 mlir-opt：观察每一步的 IR

自定义的 gdn-opt 与树内 mlir-opt 共享同一套命令行界面，调试旗标是通用的。最常用的三个：`--mlir-print-ir-after-all` 在每个 pass 之后打印完整 IR（配 `--mlir-print-ir-before` 可锁定单个 pass 的前后对照）；`--mlir-pass-statistics` 输出每个 pass 的重写次数与模式命中率，用于确认一条重写模式是否真的被触发（写了模式却从未匹配，是 pass 开发最常见的静默失败）；`--verify-diagnostics` 与源文件里的 `// expected-error` 注释配合，把"这条非法输入必须被 verifier 拒绝"变成可回归的测试。本项目方言仓库里的冒烟文件就是按这个思路组织的：

```
// dialect/test/smoke_l0.mlir —— gdn-opt 冒烟：parse + verify + gdn-to-chunk 改写
```

一条命令完成"能解析、能过 verifier、能被入口 pass 改写"三级验证，这是第十五章那段前后 IR 对照的来源。更细粒度的调试用 `--debug-only` 加源码里的 DEBUG_TYPE 标签，把日志打开到单个 pass 内部；日常开发主要依赖前三个旗标。

### 2. 期望输出测试：让 IR 回归可自动化

MLIR 树内使用 FileCheck 做模式匹配测试：测试文件里写若干 `// CHECK:` 行，逐行断言输出中包含指定的 IR 片段。它匹配的是结构片段而非全文快照，所以 IR 的无关变动（例如值编号重排）不会误报。本项目的测试策略分两层：方言层用 smoke 文件加脚本断言（parse/verify/改写三级），管线层直接以树内的 sm_80 transform-mma 集成测试做冒烟——文件名沿用上游目录名，chip 重定向为 sm_120a 后在 5090 上编译运行；sm_120 的张量核即 Ampere 风格 mma.sync，同指令族故该测试有效（第二十四章展开）。它编译一个真实的 mma kernel 走完 transform 解释器与 NVVM 下译，能在不涉及自定义方言的情况下确认本机 LLVM 构建的这条主干链路完好。

### 3. 把证据落盘作为默认动作

调试的最高层级是让"每一步的产物"本身成为可存档的证据。本项目的每个里程碑目录（evidence/G0 至 G7）都保存了当时的完整中间产物：L1 的全量 MLIR dump（第十五、十八、十九章引用的真实 IR 即来自 evidence/G1 的存档文件）、每个配置的 payload.mlir 与 transform.mlir（evidence/G2/gen/）、每个 kernel 的 PTX 前后对与 ptxas 资源报告（第二十七、二十八章引用的 kernel.ptx / kernel_smemfix.ptx）。这个习惯的回报在两处立刻兑现：其一，正文引用的每一件展品都能回溯到具体文件与行号；其二，任何一轮性能或数值变更想要回退对照，直接取存档文件重放即可，不依赖当时的内存状态。生成器侧的配合机制是内容寻址：同种子两次生成的 MLIR 哈希相同（第二十三章），存档文件因此可以作为长期有效的对照基准。

### 4. 工具链上的三个观察点

下降到目标代码之后还有三个观察工具，详细用法在第二十四章与第二十九章展开，这里给出定位：ptxas 的 `-v` 旗标输出每个 kernel 的寄存器数、共享内存字节数与溢出计数，是 L2 层静态资源复核的数据源；nvdisasm 把 cubin 反汇编成 SASS，用于指令级计数（成本模型的分子）与 bug 定位（一次缺陷的根因曾表现为 SASS 与正确版本恰好差一条指令）；compute-sanitizer 在真机上捕获越界访问与共享内存越界写。三者覆盖了"文本 IR 看不到的层"的全部观察需求。
