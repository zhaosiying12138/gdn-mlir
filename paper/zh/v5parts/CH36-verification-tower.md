## 三十六、验证塔：从 JAX 规约到逐位复现

凭什么相信产物——这个问题此前各章反复引用，却从未正面展开。本编译器从语义 op 到 cubin 要经过五层下降、数千行生成代码、四个 PTX 后处理改写，任何一处都可能引入数值偏差或时序缺陷；若只用一把尺子量到底，舍入噪声与真实缺陷会混在同一组差值里无法区分。验证的组织形态是一座四层的塔：每层针对一类被测对象配一把独立尺子，下层改动破坏语义时可回退上层口径重新对照。两个术语先定义：尺子，指裁决对错所用的参考实现或统计协议；三方交叉闭合，指三个独立实现在两两对照中距离都落到各自量程地板上、从而互为佐证的形态。塔顶的逐位复现协议与塔基的 JAX 规约是重点；容差数字本身的来历在下一章。

### 1. 塔的总览：四层、四把尺子

直觉：验证必须分层，因为每层的误差来源不同——语义层怕的是算法形态弄错，配置层怕的是资源申报失真，机器层怕的是数值映射与数据通路出错，全链层怕的是 kernel 间的时序。一把尺子覆盖不了四种失败模式。机制：每层选一把与被测对象同构的尺子，且尺子本身先被验证。总表：

| 层 | 被测对象 | 尺子 | 结果 |
|---|---|---|---|
| 语义 | MLIR L1（CPU 执行） | JAX fp64 规约与 fla naive 交叉 | 前向约 6e-7 / 反向最差 6.4e-6，三方闭合 |
| 配置 | 20 个旋钮配置 | ptxas -v 资源包络加 SASS 指令组合 | 编译期静态复核 |
| 阶段 | 逐配置 GPU kernel | fp64 numpy 参考（逐位相同的 bf16 输入） | 20/20，双随机种子 |
| 全算子 | 端到端 kernel 链 | JAX fp64 参考加结构不变量 | 全部元素在容差内，每次变更后复验 |

表 7 的四行即塔的四层。配置层是纯静态的一层（第二十九章），全算子层的统计裁决在下一章。

### 2. 塔基：JAX fp64 规约与三方交叉闭合

塔基是一份可执行的规约：GDN 的数学定义用 JAX 在 fp64 下写成三条独立实现——顺序递推（按 token 逐个更新状态）、分块（chunk 化的矩阵乘形态）、jax.vjp 反向（自动微分）。规约自身先受审：JAX 自检 44/44 项，分块与顺序两条路径在 fp64 下相差 5.6e-16（fp64 舍入量级），VJP 梯度 1.2e-14，有限差分独立验证 2.3e-9。评分参考自己先过堂，这是塔的第一条纪律。三条两两距离：

| 对照 | 前向 | 反向 |
|---|---|---|
| MLIR L1 对 JAX | 7/7 用例约 6e-7（恰为 memref 打印的 6 位有效数字地板） | 六梯度最差 6.4e-6（验证门 2e-4） |
| JAX 对 fla naive | 1.2e-7 | 2.3e-6 |
| JAX 分块对顺序 | 5.6e-16 | VJP 1.2e-14 |

fla naive 对照的一个细节：fla 的 naive 参考内部固定 fp32，对照经 fp64 JAX 中转后取 fp32 口径。三条边都落到各自量程的地板（打印精度、fp32 舍入、fp64 舍入），三方闭合成立——任何一个实现在作弊，闭合形态都无法维持。这份闭合是全塔的锚：第九章以降的所有验证结论，最终都折算回这份 fp64 规约。

### 3. fp64 参考的两条纪律

阶段层的尺子是 fp64 numpy 参考，它有两条纪律。其一，位相同输入：被测 kernel 接收的输入由主机端做精确 bf16 量化，参考实现接收同一份位相同的字节——输入侧的量化噪声因此为零，差值全部来自 kernel 内部。其二，算法同构：参考按被测 kernel 的同一算法形态（同 chunk 划分、同缩放次序）在 fp64 下重算，差值只度量 kernel 数学与内部截断，而不度量算法选择。两条纪律合起来把"测到的差"翻译成"可归因的差"：差值要么落在预测的量化台阶上，要么就是缺陷。

### 4. 两个结构性检查与其战果

数值容差之上另设两个结构性检查：非零元计数精确一致，与实测偏差对量化预测对账。两者各自抓到过真实缺陷。非零元计数的战果：kkt 阶段的下三角应有 2080 个非零元，一次 mma 路径的验证报出 1168/2080——发射器把累加器偶数元素写到了 B-fragment 的列下标而非 D-fragment 的列下标，两条 lane 写冲突、若干列从未被写。数值容差当然也报错，但计数把缺陷定位到"写集覆盖"这一层。原始记录：

```
`frag_epilogue` stored the accumulator's even elements at column
`ncol + %g` -- the lane's B-fragment N index -- instead of the
accumulator/D-fragment N index `2*threadID_in_group`. Result: two lanes
wrote conflicting values to the same columns while other columns were
never written (kkt: 1168/2080 cells covered; o: 2304/4096).
... After the fix every mma config writes all 2080 kkt tril cells / all
o cells and matches the fp64 twin at 9.77e-4
```
［evidence/G4/GATE_REPORT.md:60-78，节选；一行语义修复波及 11/20 个配置］

量化对账的战果：修复后 mma 路径实测最大偏差 9.77e-4，而管线仿真（f32 累加加 bf16 输出量化的精确 numpy 模拟）预测 9.765625e-4——实测与预测相等到最后一位。这条对账证明残差是输出量化而非计算误差，第三十一章的精度分析由此获得一块干净的地基：测到的差就是理论说要有的差。

### 5. 运行确定性：逐位一致的尺子

数值容差对一类缺陷天生无感：竞态。共享内存里读到陈旧但合法的字节，差值常在 1e-14 量级、1–3 个 ulp，任何容差门都会放行。塔顶因此用逐位一致做尺子：同一 cubin、同一输入、同一发射几何，输出必须逐位相同；且必须在跨进程条件下验证——全新 CUDA 上下文、全新模块加载，重复五次全过方为通过。跨进程是关键：本仓抓到过五个真实竞态，全部在数值容差之内、多数仅 1–3 ulp，其中两个曾被更高的驻留占用掩盖；进程内循环对它们必要而不充分——wyb 的一个竞态，同进程十次循环从未复现，只有新进程模块轮换才显形：

```
7. Determinism proof protocol for any change touching these paths:
   tools/gdn_det_check.py fresh-process N=10 BOTH shapes (the T2048
   in-process loop alone did NOT catch the wyb race pre-fix --
   fresh-module cycling is the wider window) + verify 6/6.
```
［evidence/G5/bwd_report.md:1649-1651，缺陷清单第 7 条，逐字；竞态根因记录在同文件 1516-1575 行，bpre 单 kernel 千次轮换 14/1000 双稳态 1-3 ulp 的隔离实验在 1535 行］

逐位一致的代价有账可查：修复全部竞态引入的屏障使 T2048 反向端到端慢约 0.3%（同窗交错配对实测；T512 上淹没在窗口噪声里）［evidence/G5/bwd_report.md:1675-1689］。用 0.3% 换一把能看见 ulp 级缺陷的尺子，这笔账在本仓每次都判值得。

### 6. 编译确定性：验证视角

塔的最后一层在编译端。求解器固定声明序、固定种子 7、资源上限固定，两次完整编译逐字节一致；生成器同种子两次生成的 MLIR 哈希相同；全部旋钮关断时产物与默认配置逐字节等价（27/27 payload、18/18 cubin）。完整的机制展开见第九章；从验证视角它只贡献一件事：验证塔的每一个结论都附着在字节可复现的工件上——今天验证通过的 cubin 与明天 CI 里重新编译出的 cubin 是同一串字节，验证结论因此可存档、可 diff、可断言，而无需随构建漂移重测。
