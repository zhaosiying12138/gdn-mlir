## 三十二、算法级改写：扫描的仿射携带形式

编译器的分层里有一类变换既不属于调度（不改 tile 与流水）、也不属于指令映射（不改精度位点），它改写算法本身的结合方式——把一条串行递推重新组织成可并行的形状。反向状态扫描的仿射携带改写是这类变换的标本，实测兑现三倍提速。术语先定义：余切（反向传播中损失的别名）、dH（状态矩阵的梯度）、携带（递推中从上一块带到下一块的量）、ulp（最后一位单位，浮点误差的最小刻度）。

### 1. 问题：8 段 GEMM 的串行链

反向的旧形态把逆时间行走装在一个 kernel 里：每 chunk 要装配 P、Bhat、Qg、W 四组操作数、执行两个方向的乘积注入、更新 dH，合计约 8 段 GEMM 级段落；三个消费 pre-update 状态的部分和（dk 的 Bhat 项、dg 的前缀项与状态衰减常数）也全部钉在链上。串行链的每一段都要等上一段——任何并行度扩张都被这条链吃掉。该 kernel 阶段耗时 2.17 毫秒（T2048），是反向链的最大单件。

### 2. 重结合：仿射携带形式

顺序更新每 chunk 两式：dvp 等于 P 转置乘 dO 加 Bhat 乘 X；X 的更新等于衰减乘 X 加两路注入减 W 转置乘 dvp。把第一式代入第二式并按 X 与 dO 收集，得到

Xₙ₋₁ = Aₙ·Xₙ + Bₙ，其中 Aₙ = 2^gcl·I − Wₙᵀ·Bhatₙ，Bₙ = (Qgₙᵀ − Wₙᵀ·Pₙᵀ)·dOₙ

这是代数重结合：全部乘积保留、零近似、零丢弃。Xₙ 恰是到达块 n 的 dH（pre-update 契约值，下游 kernel 消费的正是它）。验证纪律有一条专门设计：对照对象是保留 dvp 中间量的真顺序形式（fp64），避免用复合式验复合式。实测：复合式与真顺序式（含 dh0）的最大偏差 4.9e-17 与 8.3e-17——在 X 范数约 130 的尺度上为 2 至 3 ulp，机器精度地板。按 GPU 操作数精度做的 fp32 回放预测重结合底噪 1.2e-8，GPU 链内实测 2.2e-8，恰落在预测上。

### 3. 三部分拆分

仿射形式把钉在链上的工作拆成三层。并行预复合层：三个 grid 为 B·H·NC 的纯并行 kernel（caryA、caryM、bpre）每块独立造出 Aₙ、Mₙ、Bₙ 存入全局。携带链本体：dhs 每 chunk 只剩一个 GEMM——Xa 取 B 切片，Xa 加上 A_all 乘 X，X 换成 Xa——外加两次搬运；没有操作数装配、没有部分和。独立重算层：三个部分和是 dh_all 的逐块纯函数（顺序行走本来就先存 pre-update 值再更新），dkb 在行走结束后完全并行重算，顺带把跨切片归约也折进全局求和。

效果对账（T2048 同窗配对）：旧 kernel 2.17 毫秒换成四个预复合 kernel 合计 1.76 毫秒，dkb 从 0.96 降到 0.25 毫秒；扫描族整体从 3.13 毫秒降到约 1.02 毫秒。族内的顺向重算 kernel 同步重建后，T8192 从不可编译带进可建可验——旧形态把每块 gc 累积行停进共享内存，池随块数线性增长，128 块的形状直接越过 101,376B 静态上限；新形态把累积提升为序言、消费侧只留两行乒乓，池与块数解耦。

### 4. 两个数学性质

性质一，算子超收缩。基准门分布下逐块算子的谱半径与范数实测为：谱半径不超过 2.3e-18，范数不超过 2.2e-17——门控累积强负，衰减因子把块间耦合一步之内压死。工程含义：复合误差不随链长放大，串行链在数值上温顺；段切分一类的更强并行化在此分布下天然无物可赢（被丢弃的耦合项远低于 bf16 分辨率）。系统完整执行精确的一级递推，正确性不依赖门分布——弱门分布下算子范数可达 O(10)，截断即错误，超收缩只解释温顺、不承诺普适。

性质二，Aₙ 与 v 切片无关。A 只依赖 W（f32）、k（bf16）、g——不含任何 v 或 dO 分量。一个 K×K 算子每块只复合一次，即服务全部 v 切片的行走；只有最后一步 Bₙ = Mₙ·dOₙ 按列切分。预复合的工作量被切片数摊薄，这是拆分在存储流量上也占优的原因。

### 5. 方法论：变换住在生成器里

这次改写的实现形态是"算法优化怎么进编译器"这个问题的本仓回答。数学先行：CPU 孪生脚本先对真顺序形式逐位验证，把主张、推导与验证项写进可执行的文档串——

```
CLAIM (from the L1 bwd math / the dhu emitter): the reverse scan is an
affine linear recurrence per chunk n,
    X_{n-1} = A_n X_n + B_n,     X_{NC-1} = dht,
with X_n = dH ARRIVING at chunk n (exactly what dhu stores to dh_all[m]
PRE-update and what dkb/dqkwg consume), and
    A_n = 2^gcl I_K  -  W^T Bhat            ([K,K]; vt-INDEPENDENT)
    B_n = M_n dO_n,  M_n = Qg^T - W^T P^T    ([K,V] per v-slice)
```

［tools/gdn_carry_validate.py:2-14，模块 docstring 节选；脚本对 fp64 顺序轨迹、二级段分解、fp32 回放、谱条件数四类检查］

GPU 侧的变换全部写成 Python 发射结构的改写：一个 kernel 的发射函数换成四个 kernel 的发射函数，中间量的全局契约（A_all、M_all、B_all、dh_all）同步写进发射清单与 harness。没有运行时开关、没有两套代码并存——发射结构即规格，第二十三章"生成器即未来 L1 展开 pass 的可执行规格"在算法层的投影。CPU 孪生同时把二级段分解（段内零种子局部走、段算子复合、串行边界链、后缀积修正）对每个段数取值验证到同样的 2 至 3 ulp——更强的并行化在数学上同样精确，装机与否留给测量。正确性由分层验证把关：fp64 参考逐位对照定方向，逐配置 GPU 对照定落地，端到端六梯度合同定放行；下层任何调度改动破坏语义时，回退 fp64 参考重新对照的通道始终在场。旧 kernel 退役后在文件中保留作 A/B 基准——它的串行结构正是新形态全部收益的对照面。

### 6. 效果与边界

扫描族整体 3.13 毫秒降到约 1.02 毫秒，占反向端到端约 46%。边界同样测绘清楚：把扫描按 K 维拆到多 warp 或多 CTA 的三个独立数据点均在 0.88 至 0.99 之间（第三十五章的负结果物理）；段切分在超收缩分布下数学可行、经济为负。改写后的收益上限被串行步的延迟瘦身提前吃掉——这条边界与第二十八章的合并陈述一致：把工作移出串行链、压缩每步暴露延迟、纯列并行增开 CTA，是扫描类结构上仅有的三类有效手段。
