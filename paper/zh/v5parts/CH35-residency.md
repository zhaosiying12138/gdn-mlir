## 三十五、驻留资源：生存期别名与寄存器上限

一个 kernel 跑得快的门槛性条件是驻留：每 SM 同时容纳的 CTA 数。驻留由两份静态资源决定——每 CTA 申报的共享内存池与每线程寄存器数；两份资源各有硬件常数，越线即驻留减半。算法需要的 tile 生存期拼接远超门槛，任意时刻真正活跃的字节却在门槛之下；生存期别名把这一物理事实安全地施加到产物上，负结果则测绘驻留杠杆的适用边界。术语先定义：生存期（一个 tile 从写入到最后一次读取的区间）、别名（多个生存期不重叠的 tile 共享同一块字节）、竞技场（被多个 tile 共享的基地址块）、占用（每 SM 实际驻留的 warp 数占上限的比例）。

### 1. 双 CTA 门槛与生存期拼接的矛盾

sm_120a 的共享内存每 CTA 上限为 101,376B，而每 SM 同时驻留两个线程块要求每 kernel 静态共享内存池不超过约 50.2 至 50.7KB（按 ptxas 补齐口径；第三十章 F1KS 的前向保守申报线取 49,152B）。反向三个大 kernel 的 tile 分配字节之和都在 100KB 上下：dqkwg 100,864B、caryA 82,176B、wyb 100,096B。矛盾由此而来： SSA 合法性要求每个 tile 一次分配、地址互不重叠，而"生存期不重叠的 tile 可以共享字节"这一物理事实在 IR 层表达不了——支配性与活性分析在 SSA 世界里没有"这块字节已经没人读"的载体。施加点因此下放到 PTX 层：生成器声明布局，后处理改写地址。

### 2. 布局表与识别回退

生成器为每 kernel 产出一份 smem_alias.json：identify 按 malloc 尺寸识别 tile 名，arenas 声明竞技场基 tile 及其字节数，alias 把每个被折叠 tile 映射到基 tile 加偏移。前向 F1 的布局表原文：

```
"gdn_fwd_f1_kernel": {
 "identify": { "9216": "Abf", "9504": "Tt", "8704": "vt", "8976": "k2" },
 "arenas":   { "Abf": 9216, "Tt": 9504 },
 "alias":    { "vt": ["Abf", 0], "k2": ["Tt", 0] }
}
```

［evidence/G5/gen_fwd/B4T2048_mono/smem_alias.json；两个半尺寸 tile 分别折叠进两个竞技场的死字节］

识别按尺寸、按唯一性：LLVM 会重排 malloc 序列，尺寸是唯一稳定的锚；同一尺寸出现多次即整体弃用别名。弃用的形态与无别名构建完全一致——设计立场是别名属于纯增益变换，失败模式必须是"不省"，绝不允许"算错"。识别与回退的完整机制、PTX 前后对照与三条硬规则（分裂永不别名自身源、epilogue 跨界写读的栅栏、异步落地的消费纪律）在第二十八章。

### 3. 三个池压缩

别名与退役（第三十一章 caryA 的四 tile 整体退役）合力把三个大 kernel 压过门槛：

| kernel | 压缩前 | 压缩后 | 手段 |
|---|---|---|---|
| dqkwg | 100,864B | 47,616B | 双竞技场别名加 epilogue 停车 |
| caryA | 82,176B | 28,592B | split 拆分式移植，四 tile 退役 |
| wyb | 100,096B | 45,056B | 双竞技场别名 |

三个 kernel 全部达成双 CTA 驻留，dqkwg 实测每 SM warp 数从 7.59 升到 14.53。前向 F1 走同一条路：半尺寸 tile 折叠进求解之后的死字节，申报池 46,352B 过线（第三十章 F1KS）。别名与退役是同一谱系的两端——前者复用字节，后者消灭需求；caryA 的案例说明当生存期结构不允许合法别名时，换一套更省 tile 的算法形态才是出路。

### 4. .maxnreg 与 setmaxnreg 的分工

两个名字相近的机制各管一层，混用即失效。.maxnreg 是 PTX 后处理注入的逐 kernel 寄存器上限：ptxas-blackwell 忽略命令行旗标、遵循 PTX 源内的 .maxnreg 指令，且装着多个 kernel 的单一 cubin 本来就需要逐入口注入——f3 想要 168、f2 想要 128 时，一个文件级旗标给不出两个数。注入工具按环境变量表对入口名做子串匹配、未匹配显式告警；对账必须读改写后第二次编译的报告（第二十九章的双遍陷阱）。注入后占用从 15.02% 升到 29.17%、每 SM warp 数从 8.00 升到 14.23。gdn.setmaxnreg 是 kernel 内部的运行时寄存器再分配：warp 专化下生产者 warp 让出寄存器、消费者 warp 领走（第三十三章）。前者的作用对象是驻留（占用上限），后者的作用对象是占用内部的分配（溢出）——实测某 warp 专化 kernel 的溢出从 22,844B 降到 48B，靠的正是后者加 TMA 把装载指令数砍掉三个数量级。

### 5. 负结果的物理

驻留提升是杠杆还是空转，取决于 kernel 的受限模式；负结果把这条边界测绘得比正结果更清楚。

F1 与 F3 的对照。F1 停顿的 24.3% 来自访存等待、DRAM 利用率仅 56.8%——延迟受限，驻留翻倍直接转化为延迟下降 53.5 微秒。F3 每次加载约 120MB——带宽受限，同样的驻留手段实测反慢 96.1 微秒。分解测量把账算清：同一份重构代码强制单 CTA 驻留为 115.6 微秒，其中 K 循环重排本身约 110 微秒（循环与同步的迭代数翻倍），驻留只买回约 20 微秒——重构的代价在先，驻留的收益在后，净值注定为负。

串行扫描的 K 维拆分。把扫描工作按 K 维拆到多 warp 或多 CTA（含线程块簇形态），三个独立数据点均在 0.88 至 0.99 之间：每 warp 工作量不变时，指令级并行已在 warp 调度器层面饱和，剩余延迟由数据搬运与同步构成，拆分只是把这些延迟换了位置。簇的分解测量单独值得记录：同一 kernel 挂 2×1×1 簇属性发射，耗时 722.8 微秒、恰为不挂属性时 361.4 微秒的两倍（发射的 CTA 数按簇尺寸翻倍、时间精确翻倍）——簇属性本身零开销；带交换的拆分形态与基线的全部净差是 57 微秒的跨 CTA 数据交换成本（停车写、系统域原子往返、多一遍全局读）。顺带一项对先例的推翻：sm_120 线程块簇大于 1 可用，设备端读取簇秩的探针证明硬件真以簇模式执行——"消费级 Blackwell 只支持 1×1×1 簇"的通行假设对本设备不成立。

三条负结果合起来的定律与第三十二章的合并陈述同源：驻留与并行度扩张只在延迟受限处付钱；带宽受限与每执行体工作量不变两种形态下，它们换不来时间。判据全部可编译期预判——停顿构成、流量字节数、每 warp 工作量都是生成器与成本模型手里的静态量。
