## 三十一、数值到指令：split-bf16 的完整工程

反向链的多数 GEMM 有一侧操作数必须是 fp32 中间量，而这些中间量存在大数相消——真实量级 O(0.1) 的值由若干 O(10) 的项相减得到，任何读取侧的舍入误差都恰好砸在被相消后的小值上。张量核对这类乘积提供的三种现成精度各有缺口，split-bf16 是第四条路：把一个 fp32 值拆成两条 bf16，用三条张量核乘法恢复 fp32 质量的乘积。术语先定义：bf16（8 位指数加 7 位尾数的浮点格式）、tf32（10 位尾数、保持 fp32 指数域的张量核格式）、mma（张量核矩阵乘指令）、位点（一处 GEMM 调用位置）。

### 1. 为什么需要：三种现成精度的裁决

bf16 的 7 位尾数装不下 fp32 中间量——把 O(10) 的项各自舍入就引入 4.6e-2 至 6.9e-2 的绝对误差，超出容差 2.4 至 11 倍。tf32 把尾数保到 10 位，双操作数截断约 2^-11 量级，在 dkb 位点的实测把 dk 输出误差推到 1.04e-2，超出 8e-3 容差——路线被逐点数值门否决。fp32 路径没有张量核速度（标量环每乘加约 5 至 6 条指令）。split-bf16 的立项理由由这组对照给出：乘积残差约 2^-17，比 tf32 的截断低约 30 倍，同时全部乘法走 mma。

### 2. hi/lo 的数学

对 fp32 值 x 定义 hi = bf16(x)、lo = bf16(x − hi)。hi 携带前 8 位尾数，lo 携带接下来的约 8 位；hi + lo 在 fp32 中精确可加——8 加 8 位尾数装得进 24 位，这个"精确可加"是整个体系的地基。乘积展开为四项：hi·hi、hi·lo、lo·hi、lo·lo；末项约 2^-32，舍弃；前三项以 bf16 mma 发射、fp32 累加器链接，乘积残差落在约 2^-17 量级。残差来源只剩 lo·lo 与累加器舍入，两项都在容差之下的深处。

有一个必须先立的边界：split-bf16 提升乘积精度，节省不了存储流量。hi 与 lo 都要落盘（各占 bf16 的两字节，合计恰是 fp32 的四字节），读取侧同样两份全读——它能换的是计算精度与张量核吞吐，换不来字节数。这解释了它为何只出现在乘积位点上：凡是被中间量字节流量卡死的地方（第三十九章的误差预算），split-bf16 帮不上忙；凡是被乘法吞吐与精度卡死的地方，它是标准答案。

### 3. 两遍拆分发射与屏障的必要性

拆分的发射是两遍扫描：第一遍截断出主部 hi，第二遍对残差截断出 lo。

```
# 第一遍：hi = bf16(v)
%sh = tid + j*nthr;  i, j = %sh/Cc, %sh%Cc
%v  = load src[i, j]              # 可选乘精确 2 的幂列尺度 cvec
%sht = arith.truncf %v : f32 to bf16
store %sht, hi[i, j]
gpu.barrier                       # hi 全部落盘后才能算残差
# 第二遍：lo = bf16(v − hi)
%h  = load hi[i, j]
%r  = arith.subf %v, %h : f32
%slt = arith.truncf %r : f32 to bf16
store %slt, lo[i, j]
```

［tools/gdn_bwd_gen.py:1398-1422（_split_bf16），两遍间的 gpu.barrier 在 1410 行］

屏障的必要性来自数据依赖本身：第二遍的残差 v − hi 需要同地址的 hi 已写入，而 hi 的格子由全部线程在第一遍分散写入——没有这道屏障，任何线程都可能读到未填充的 hi 格子。拆分因此结构性地是两遍，任何把它合并成一遍的写法都要重算 v 的来源。

### 4. 三链调用与真实 PTX 的对照

dkb 位点把两个操作数各拆一次，然后三次 mma_gemm 以 accs 参数串进同一组累加器：

```
_split_bf16(e, vh, vl, vngb, C, BV)      # vnew → hi/lo
_split_bf16(e, hh, hl, cur, K, BV)       # h     → hi/lo
maccs = mma_gemm(e, "dkBhh", C, K, BV, 8, vh.name, vh.ty, hh.name, hh.ty, accs=maccs)
maccs = mma_gemm(e, "dkBhl", C, K, BV, 8, vh.name, vh.ty, hl.name, hh.ty, accs=maccs)
maccs = mma_gemm(e, "dkBlh", C, K, BV, 8, vl.name, vl.ty, hh.name, hh.ty, accs=maccs)
```

### 5. 两条省一条 mma 的代数

三链是通用形态，两条代数性质在特定形状下各省一条 mma。

其一，行尺度折入 epilogue：当缩放因子只依赖输出行（不依赖缩并下标）时，缩放可以完全移出缩并、在 epilogue 做一次标量乘——A 操作数退化为原始 bf16 切片，无需分裂。dvp_bh 位点由此从 3-mma 降为 2-mma。

其二，2 的幂尺度可交换性：split(v·2^d) = split(v)·2^d 精确成立——2 的幂只移动指数域、不碰尾数舍入，hi 与 lo 同步缩放，残差同步移动。生成器 docstring 给出证明［tools/gdn_bwd_gen.py:941-949］。caryA 借这条恒等式把 Bhat 行尺度折进 A 侧拆分，B 操作数退化为原始 k 的转置暂存（全局本来就是 bf16，逐字节精确）：

```
v = load src[m, col(j)]                 # 全局装载
if cvec: v = v * ldsc(cvec, s)          # 精确 2 的幂列尺度，可进 split
%puh = arith.truncf v : f32 to bf16     # hi
store %puh, hi[j, s]
%puw = arith.extf %puh : bf16 to f32
%pul = arith.truncf (v − %puw) : f32 to bf16   # lo = bf16(v − hi)
store %pul, lo[j, s]
```

［tools/gdn_bwd_gen.py:956-969，stage_split_T 循环体；2-mma 用法见 7652-7658 行注释］

这条恒等式的工程后果：caryA 的预乘 tile 整体退役，共享内存从 82,176B 降到 28,592B，寄存器从 255 降到 76，该 kernel 提速 5.00 倍——改结合方式而不改任何值的机器级表达。

### 6. 效果：速度与误差同时改善

dkb 位点：内核从 0.96 提速到 0.25 毫秒（3.8 倍），dk 输出误差 1.73e-3（对 fp64 参考），与标量 fp32 路径的 1.731e-3 统计不可分——拆分在数值上近乎免费。

全家族推广分两批落地。wyb 的七个 tf32 与补偿求和位点全部改写为 2 至 3 链 split，共享内存池从 100,096B 降到 45,056B（第三十五章的驻留账）、寄存器恰 128，dk 从 1.691e-3 收紧到 1.284e-3，dβ 与 dg 的容差裕度分别扩大 23 与 61 倍，dh0 扩大 36900 倍。dqkwg 的三处 tf32 尾部同批改写：cp.async 从 46 条清零、共享标量读从 1234 降到 71、栈泄漏 72B 清零，dq 从 4.910e-4 收紧到 1.824e-4（裕度从 7.5 倍扩到 44 倍）。与被否决的 tf32 对照：1.73e-3 对 1.04e-2，误差低约 30 倍，恰为 2^-17 残差对 2^-11 截断的比值。

split-bf16 由此成为 tf32 不可用位点的标准路线：一条 mma 的速度、一条 fp32 乘积的精度、两条恒等式换来的 mma 数量折扣。它的每个环节——两遍发射、三链累加器、尺度折叠——都只依赖 bf16 截断的初等性质，没有任何一条依赖输入分布；这个"不挑食"的特性使它可以无条件铺满全链，而 tf32 的逐位点门（24 个位点里 8 个被否决）必须逐个测量放行。
