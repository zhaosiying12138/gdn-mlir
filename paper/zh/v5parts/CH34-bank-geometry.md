## 三十四、存储几何：bank 冲突的读侧与写侧

共享内存的物理组织决定一条访存指令的真实代价：同样的字节数、同样的对齐，访问地址落在 bank 上的分布不同，耗时可以差八倍。编译器看到的只有地址与对齐；哪个 tile 以什么行距被哪条指令消费，是生成器的知识。存储几何的问题分两类——读侧（ldmatrix 的行距冲突）与写侧（32 位宽存 store 的配对冲突）——它们只能在生成器层解决。术语先定义：bank（共享内存按地址取模划分的 32 个独立存储体，每体 4 字节宽）、bank 冲突（同一 warp 的多条访问命中同一 bank 的不同字，硬件被迫串行服务）、ldmatrix（张量核操作数片段的装载指令，一条读 8 行 × 16 字节）、行距（tile 相邻两行的字节距离）。

### 1. bank 组织原理

共享内存的每一 128 字节行被切成 32 个 bank，每 bank 4 字节宽、独立服务一个请求。一个 warp 的 32 条访问若落在互不相同的 bank，硬件一个周期服务完毕；若有多条命中同一 bank 的不同地址，这些访问串行化——n 路冲突意味着 n 次串行服务。冲突的判定只依赖地址对 128 字节窗口的分布：两个地址相差 128 的整数倍时必然同 bank。这个取模几何正是行距敏感性的来源：一个二维 tile 里，行号加一、列号不变的两条访问，地址差恰为行距。

### 2. 读侧：垫行

ldmatrix 一条指令让一个 warp 读 8 行、每行 16 字节。当 tile 行距恰为 128 字节整数倍（64×128 的 tile 行距 128B、64×256 行距 512B，以此类推），8 行的起点相差 128 的倍数——全部落在同一组 4 个 bank 上，8 路冲突，一条装载串行服务 8 次。前向 F2 曾长期滞留于此：实测每 SM 约 40 周期才完成一条 LDSM、发射间隔 63% 停在 MIO 队列满、每调度器仅 2 个活跃 warp。

修复是给每个被 ldmatrix 读取的 tile 加 8 列 bf16 垫（16 字节）：行距变为 128 的倍数加 16，8 行起点依次错开，一条装载的 8 行轮换扫过全部 32 个 bank；加 16 字节同时保持 cp.async 的 16 字节对齐。发运 payload 里每个 LDSM tile 都带垫——F2 的 wb 为 64×264、kb 为 128×136、S 为 128×40、vn 为 64×40，F1 的 Abf 为 64×72。垫列永不写永不读，唯一的职责是移动行距。效果：F2 从 473 降到 249 微秒，前向单笔最大杠杆；F1 与 F3 的全部同类 tile 同样受益。一笔诚实的附注：垫在 F1 与 F3 上的具体收益被各自当时的其它瓶颈掩盖，两处的垫照加——几何规则按 tile 类别统一执行，不按当前瓶颈选择性豁免，否则每次调度变动都要重验 bank 安全。

### 3. 写侧：WST 配对与 W32P 重映射

写侧的问题是共享内存到全局的逐 cell 16 位搬运。WST 旋钮让生成器把搬运发成成对单元（相邻两 cell 一次处理），PTX 后处理再把四条指令融合为两条——32 位共享读加 32 位全局写，字节精确等价（32 位字恰好装下两个相邻 bf16），指令与循环迭代减半。WST 带一条结构性守卫：列数不少于 64 的行才自动配对——F1 与 F3 的 128 列行保证一个 warp 的配对读全落在一行内；F2 的 32 列不满足守卫，配对必然跨行，写侧因此需要自己的几何解。

直接把 WST 套到 F2 上是负收益，失败有精确的几何解释。F2 的 BV=32 tile 行距 80 字节即 20 个字；配对后一个 warp 的 32 条 32 位读要跨两行，lane 28 至 31 与 lane 0 至 3 的字地址恰好撞进同一 bank——2 路冲突，实测反慢 4.3 微秒。

W32P 的解保持配对读写，只改行映射：lane 0 至 15 映射到行 r、lane 16 至 31 映射到行 r+4。字地址账：行 r 的 16 对占字 20r 至 20r+16；行 r+4 占 20r+80 至 20r+95；80 mod 32 = 16，两个半 warp 的字地址恰好命中 32 个 bank 的两个互补 16-bank 半区——对每个 r 冲突清零。覆盖是双射：轮 j、warp w、半区 h 映射到行 8j+w+4h，h 取遍 0 到 7 时恰好覆盖 8 行各一次。发射侧的重映射是纯下标算术：

```
hi16 = cmpi uge %lane, 16                     # 是否高半 warp
hi4  = select hi16, 4, 0                      # 行槽 +4
hcol = %warp + hi4                            # 半 warp 行槽 0..7
c0   = (%lane % 16) * 2                       # 列基：2*(lane%16)

def body3(i):                                 # 每线程逐元素循环
    k   = i / nthr                            # nthr=128，即 i>>7
    row = k * 8 + hcol                        # row = 8*(i>>7)+warp+4*(lane>=16)
```

### 4. 编译器为何看不到 bank 几何

PTX 与 IR 里的访存指令携带地址和对齐，不携带 bank 语义；一个 tile 的行距、它将被 ldmatrix 还是标量读消费、哪个 warp 在哪一步以何种 lane 映射访问它——这些事实分散在调度的全部决定里，只有发射它们的生成器完整持有。stock 管线能做地址合法性与对齐检查，做不了"这个行距在这个访问模式下冲突几路"的判断，因为后者需要同时知道 tile 几何与消费指令的访问模式。本编译器的处置因此是双向的：bank 无冲突作为发射期的构造性质——被 ldmatrix 读的 tile 一律带垫（第 2 节）、W32P 的映射以恒等式保证互补半区（第 3 节）；构造的有效性由实测画像复核——ncu 的 MIO 队列停顿、LDSM 完成间隔、占用与池数字都进了证据目录。几何规则错误时的兜底同样明确：访问模式的任何改动（比如 warp 映射换形）都会使旧垫失效，垫因此跟 tile 声明走、跟消费指令走，在生成器里同处一地。

写侧与读侧合起来看，存储几何是"调度即 IR"论点在物理层的对偶：调度知识以发射结构承载、可 diff、可审计；bank 几何是其中最贴近硬件的一层，它的每个决定都以垫的列数或一条下标算术的形式落在 payload 里，错误时逐位可追。
